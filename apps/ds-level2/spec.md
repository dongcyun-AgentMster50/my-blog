# 데이터 사이언스 레벨2 학습앱 (ds-level2) — 설계 문서 (spec)

"데이터 사이언스 레벨2" 시험(필기: 개념·용어·코드 읽기 / 실습: Jupyter에서 데이터를 처리해 값을 구함)에 대비하는 학습 웹앱이다. 사용자가 준 **학습 색인(파트 A 전처리 4챕터 21토픽, 파트 B 운영자 비법 5챕터 + 5개 이해도 점검 노드)** 을 커리큘럼 트리로 1:1 반영하고, 노드마다 **요약 카드(cheat sheet) → 필기 퀴즈(약 410문제, 해설·영문 병기 용어 포함) → Jupyter 실습 과제(약 60개, 값 입력 채점)** 의 흐름으로 진도를 쌓는다. 오답 노트, 라이트너(Leitner) 간격 반복 복습, 모의고사, 용어 사전을 갖추고, 진도는 `localStorage`에 저장하며 JSON으로 기기 간 이동한다. 실습은 앱 안에서 Python을 실행하지 않고, 셀 복사와 `.ipynb` 다운로드로 사용자의 개인 Jupyter Notebook에 넘긴다. 프레임워크·번들러·외부 라이브러리 없이 순수 HTML/CSS/JS로 `/apps/ds-level2/` 안에서 자체 완결되며, `file://`로 열어도 동작하고, 출퇴근길 스마트폰 사용을 1순위로 한 모바일 우선 단일 페이지(해시 라우팅) 앱이다.

### 콘텐츠와 엔진을 분리하는 이유

- **병렬 작성.** 콘텐츠 파일 11개는 서로를 참조하지 않고 각자 `DS2.register(...)`만 호출한다. 에이전트 11명이 동시에 서로 다른 파일을 써도 머지 충돌이 없다. 엔진 에이전트는 `data/` 폴더를 건드리지 않고, 콘텐츠 에이전트는 `js/`를 건드리지 않는다.
- **스키마가 계약이다.** 엔진은 3절의 스키마만 알고, 콘텐츠는 스키마만 지키면 된다. 그래서 두 작업이 **동시에** 시작될 수 있다(9절).
- **원본 하나.** 실습 노트북(`.ipynb`)을 저장소에 따로 두지 않고 문제 데이터에서 생성한다(6절). 정답·힌트·셀이 한 곳에만 존재해 불일치가 생기지 않는다.

### 왜 챕터 단위, 왜 11개인가

- 토픽 단위(31파일)는 파일이 너무 잘게 쪼개져 로드 순서·`<script>` 태그 관리가 번거롭고, 에이전트 31명은 조율 비용이 크다. 챕터 단위(9파일)가 자연스러운데, **파트A 2장(6토픽: 72문제+18실습)과 3장(7토픽: 84문제+14실습)은 한 에이전트 분량으로 너무 크다.** 품질(특히 해설의 정확성과 실습 정답 검증)이 떨어지므로 둘을 반으로 갈라 11개로 한다.
- 파트B는 강의 노드 + 점검 노드가 한 쌍이라 같은 파일에 둔다(강의 내용을 아는 에이전트가 점검 문제를 내야 일관된다).
- 한 파일 목표 분량: 필기 24~48문제 + 실습 6~10개 + 요약 카드 3~4개 + 용어 20~40개 = JS 800~1500줄.

### 로드 순서 (`index.html`)

```
<script src="js/registry.js"></script>        ← 반드시 첫 번째
<script src="js/curriculum.js"></script>
<script src="data/a1-sql.js"></script>
... data/ 11개 (순서 무관, 단 registry 뒤) ...
<script src="js/store.js"></script>
<script src="js/format.js"></script>
<script src="js/grader.js"></script>
<script src="js/leitner.js"></script>
<script src="js/exam.js"></script>
<script src="js/ipynb.js"></script>
<script src="js/router.js"></script>
<script src="js/views.js"></script>
<script src="js/app.js"></script>              ← DOMContentLoaded에서 부팅
```

모두 **클래식 `<script>`(모듈 아님)**, `defer` 없이 본문 끝에 둔다. 이유는 2048 spec과 같다 — ES 모듈은 `file://`에서 CORS로 막히고, `fetch()`로 JSON을 읽는 것도 `file://`에서 막힌다. 콘텐츠를 JS 파일에 담아 전역 레지스트리에 등록하면 더블클릭으로 열어도 돌아간다. 각 파일은 IIFE로 감싸고 전역은 `window.DS2` 하나만 쓴다.

### 레지스트리 API (`registry.js`) — 콘텐츠 에이전트가 쓰는 유일한 인터페이스

```js
// data/a1-sql.js 의 골격
(function () {
  DS2.register({
    chapter: "a-1",                 // 이 파일이 담당하는 챕터 id (검증용)
    cards:     { "a-1-1": {/* 요약 카드 */}, "a-1-2": {...}, ... },
    questions: [ /* 필기 문제 객체들 */ ],
    practices: [ /* 실습 과제 객체들 */ ],
    terms:     [ /* 용어 객체들 */ ]
  });
})();
```

- `register()`는 **누적(additive)** 이다. 같은 노드에 두 파일이 문제를 등록해도 합쳐진다(A2·A3 분할이 가능한 이유). `cards`는 노드 id당 하나만 허용하고 중복이면 나중 것을 무시하고 `DS2.warnings`에 기록.
- `terms`는 `id`로 병합한다. 같은 id가 다시 오면 **먼저 등록된 정의를 유지**하고, 정의 문자열이 다르면 `DS2.warnings`에 `{type:"term-conflict", id, files}`를 남긴다(Review에서 사람이 병합). 이 규칙 덕분에 콘텐츠 에이전트는 다른 파일이 어떤 용어를 정의했는지 몰라도 된다 — **자기 파일에서 태그한 용어는 자기 파일에서 전부 정의한다.**
- 등록 시점에 최소 검증(필수 필드, id 형식)을 하고 실패한 항목은 버리지 않고 `DS2.warnings`에 넣는다. 앱은 경고가 있어도 뜬다(설정 화면 하단에 경고 수 표시).
- 읽기 API: `DS2.getNode(id)`, `DS2.questionsOf(nodeId)`, `DS2.practicesOf(nodeId)`, `DS2.card(nodeId)`, `DS2.term(id)`, `DS2.allQuestions()`. 데이터 파일은 DOM/`window` 다른 속성을 참조하지 않는다(Node `vm`으로도 로드되어야 하므로).

## 2. 커리큘럼 트리와 ID 규칙 (`curriculum.js`)

트리는 색인과 **글자 하나까지 1:1**이다. 사용자가 색인 자체를 암기하는 것이 목표이므로 앱이 항목을 재배열·병합하지 않는다.

| 노드 id | 종류 | 표시 |
|---|---|---|
| `a`, `b` | part | 파트 A. 전처리 / 파트 B. 운영자의 비법 모음 |
| `a-1` … `a-4` | chapter | 1. SQL 학습 … 4. 복합 사용법 |
| `a-1-1` … `a-4-4` (21개) | topic | 1-1 SQL 기초 … 4-4 통계 검정 및 특수 모델링 |
| `b-1` … `b-5` (5개) | topic | 1. Python native 문법 익히기 … 5. 가설검정 (**챕터이자 학습 토픽**) |
| `b-1-2` … `b-5-2` (5개) | check | 1-2 이해도 점검 문제 … 5-2 이해도 점검 문제 |

- **파트 B "N-2 이해도 점검 문제"는 별도 노드(check)로 둔다.** (a) 퀴즈로 흡수하면 트리가 색인과 달라져 암기 목표를 해친다. (b) 별도 노드로 두되 종류를 `check`로 하여 요약 카드·실습 탭 없이 퀴즈만 있고 문제 수를 20개로 늘린다. 파트 B의 `b-N` 노드는 자식 `b-N-2`를 갖는 동시에 자신도 학습 가능한 토픽이다(카드·퀴즈·실습 있음).
- 학습 가능한 노드 = topic 26개 + check 5개 = **31개**.
- `curriculum.js`는 `{ id, type, title, order, parent, children, prevNext }`만 가진다. 제목 문자열은 색인 원문 그대로.
- **문제 id**: `<nodeId>-q<2자리>` 예 `a-2-3-q07`, `b-1-2-q15`. **실습 id**: `<nodeId>-p<2자리>` 예 `a-1-1-p02`. **용어 id**: 영문 소문자 슬러그(`groupby`, `p-value`, `left-join`, `type-i-error`). 영문 표기가 없는 개념은 로마자 대신 의미 영어로(`missing-value`).
- 라우트에서 노드 id는 그대로 쓴다: `#/topic/a-2-3`.

## 3. 콘텐츠 데이터 스키마

모든 텍스트 필드는 `string` 또는 `string[]`(줄 배열 — 엔진이 `"\n"`으로 합친다)을 허용한다. 배열을 허용하는 이유: 코드와 여러 줄 해설을 JS 문자열 안에서 `\n`과 백틱 이스케이프 없이 쓸 수 있다. **콘텐츠 파일에서는 템플릿 리터럴(백틱 문자열)을 쓰지 않는다** — 인라인 코드 마크업이 백틱이라 충돌한다. 큰따옴표 문자열 또는 줄 배열만 쓴다.

### 3-1. 미니 마크업 규칙 (`format.js`)

풀 마크다운 파서는 두지 않는다. 다음만 지원하고 나머지는 평문이다. 처리 순서: **HTML 이스케이프 → 코드 블록 추출 → 블록(문단/목록) → 인라인.**

| 문법 | 결과 | 비고 |
|---|---|---|
| `` `x` `` | `<code>` | 인라인 코드. 내부는 이스케이프만, 마크업 무시 |
| ```` ```python ``` ```` … ```` ``` ```` | `<pre><code class="lang-python">` | 언어: `python` / `sql` / `text`. 토크나이저 적용 |
| `**굵게**` | `<strong>` | |
| 빈 줄 | 문단 구분 `<p>` | 단일 줄바꿈은 `<br>` |
| 줄 머리 `- ` | `<ul><li>` | 1단계만. 번호 목록은 `1. `도 `<ol>`로 |
| `[[term-id]]`, `[[term-id|표시글]]` | `<button class="term" data-term="...">` | 용어 사전 팝업 링크. 없는 id면 평문으로 표시하고 경고 |
| `\|` (표) | 지원 안 함 | 표가 필요하면 코드 블록(`text`)으로 정렬해 쓴다 |

포매터는 정규식 5~6개로 끝나고, 입력을 먼저 이스케이프하므로 콘텐츠에 HTML이 섞여도 실행되지 않는다.

**코드 토크나이저**(하이라이팅 결정 — 4절 "판단" 참고): `python`과 `sql` 두 언어. 토큰 종류 5개만: `comment`, `string`, `number`, `keyword`, `decorator`(py). 한 개의 합성 정규식(`/(#.*|"""[\s\S]*?"""|'[^']*'|"[^"]*"|\b\d+(\.\d+)?\b|\b(?:def|return|…)\b)/g`)으로 원문을 1패스 스캔하며 토큰마다 이스케이프 후 `<span class="tk-…">`로 감싼다. SQL 키워드는 대소문자 무시. 약 60줄. 실패해도 최악의 경우 평문 `<pre>`가 나오므로 안전하다.

### 3-2. 토픽 요약 카드 (cheat sheet)

```js
cards: {
  "a-2-3": {
    node: "a-2-3",                                 // 필수. 키와 동일
    title: "Pandas 변환과 집계",                     // 필수. 색인 제목 그대로
    summary: "groupby-agg-transform 세 축을 구분하는 것이 이 토픽의 전부다. ...",  // 필수. 3~6문장, 마크업 허용
    concepts: [                                    // 필수. 3~8개. 각 1~3문장
      "**분할-적용-결합(split-apply-combine)**: `groupby`는 키별로 나누고, 함수를 적용하고, 다시 합친다.",
      "..."
    ],
    terms: ["groupby", "aggregation", "transform", "pivot-table"],   // 필수. 3~12개. 용어 id (사전에 존재해야 함)
    patterns: [                                    // 필수. 3~7개 핵심 코드 패턴
      {
        title: "그룹별 여러 통계 한 번에",             // 필수
        lang: "python",                            // 필수. python | sql
        code: [                                    // 필수. string | string[]
          "df.groupby('dept')['salary'].agg(['mean', 'max', 'count'])"
        ],
        note: "결과는 컬럼이 통계명인 DataFrame. `as_index=False`를 주면 키가 컬럼으로 남는다."  // 선택
      }
    ],
    pitfalls: ["`transform`은 원본과 같은 길이를 돌려준다. `agg`와 혼동하면 shape 오류."]   // 선택. 시험 함정 0~5개
  }
}
```

용어 사전 항목 스키마(`terms`):

```js
terms: [
  {
    id: "groupby",                       // 필수. 슬러그
```

## 5. 점진적 학습 설계

### 5-1. 노드 상태와 완료 기준 (`leitner.js: nodeStatus()`)

상태는 저장하지 않고 **진도 데이터에서 매번 계산**한다(저장하면 규칙 변경 시 불일치).

| 상태 | 조건 | 트리 표시 |
|---|---|---|
| 미학습 | 카드 열람 기록 없음 AND 문제 시도 0 | 빈 원 |
| 학습중 | 아래 완료 조건 미충족이나 활동 있음 | 반원 + `n/N` |
| 완료 | (check 노드는 카드 조건 제외) 카드 열람 기록 있음 AND 노드의 **모든 문제를 1회 이상 시도** AND **최근 시도 기준 정답률 ≥ 80%** | 채운 원 |

- "최근 시도 기준"이란 문제별 `last`(마지막 결과)가 정답인 비율. 처음에 틀렸어도 오답 노트에서 다시 맞히면 올라간다 — 재학습이 보상받아야 한다.
- 실습은 완료 조건에 넣지 않는다. Jupyter가 없는 출퇴근길에 완료가 막히면 안 된다. 대신 노드 옆에 `실습 1/3` 배지를 따로 표시하고, 대시보드에 실습 총 진도를 별도로 보여준다.
- 챕터·파트 상태 = 자식의 완료 개수 비율(`3/6 완료`).

### 5-2. 학습 흐름과 잠금 — **자유 탐색 + 권장 순서**

**결정: 잠금(unlock)을 두지 않는다.**
- 학습자는 중급자이고 시험 대비 목적이다. 이미 아는 SQL 기초를 억지로 통과해야 pandas를 열 수 있으면 첫날에 앱을 버린다.
- 색인 암기 목표는 "트리를 자주 보는 것"으로 달성되지, 잠금으로 달성되지 않는다.
- 대신 (1) 트리는 색인 순서로 고정, (2) 홈의 **"이어서 학습"** 버튼은 색인 순서상 첫 미완료 노드로 보낸다, (3) 토픽 화면 하단에 `← 이전 | 다음 →`(색인 순서), (4) 토픽 탭 순서는 요약 → 퀴즈 → 실습으로 고정하고 퀴즈 완료 시 "다음 토픽" 제안을 띄운다.

토픽 안의 흐름: **요약 카드 읽기(열람 기록) → 퀴즈(노드 문제를 미시도 → 오답 → 기한 도래 순으로 정렬해 출제) → 실습(셀 복사/노트북 → 값 입력) → 다음 토픽.**

### 5-3. 퀴즈 세션 규칙

- 한 세션 = 노드의 문제 전부(12 또는 20)를 **미시도 우선, 그다음 오답, 그다음 나머지** 순으로. 셔플은 그룹 안에서만(문제 순서 암기 방지). mcq 보기 순서는 **셔플하지 않는다** — 해설이 ①②③④ 번호를 참조하기 때문. 대신 콘텐츠 규칙으로 "정답 위치를 고르게 분산"(검증기가 노드별 정답 인덱스 편중 ≥ 60%면 경고).
- 한 문제: 답 선택 → [정답 확인] → 결과·해설 표시 → [다음]. 채점 즉시 `store.recordQuiz(qid, correct)` 호출(세션 중단해도 진도 보존).
- 세션 종료 화면: 정답률, 틀린 문제 목록(바로 다시 풀기), 노드 상태 변화(학습중→완료), [다음 토픽] / [실습으로].
- 이미 풀었던 문제는 프롬프트 위에 작은 배지 `상자 2 · 2회 정답`.

### 5-4. 오답 노트 (`#/wrong`)

- 정의: **마지막 시도가 오답인 문제**(`last === false`). 다시 풀어 맞히면 자동으로 빠진다. 별도 "제거" 버튼 없음.
- 화면: 노드별 그룹, 개수, [전부 다시 풀기] / 노드별 [다시 풀기]. 목록 항목을 탭하면 문제·해설을 **읽기 모드**로 볼 수 있다(풀지 않고 해설만 복습). 정렬: 틀린 횟수 많은 순.

### 5-5. 복습 스케줄 — **라이트너(Leitner) 4상자 채택**

**넣는다.** 필기 400문제를 한 번 풀고 끝내면 시험 때 남지 않는다. 규칙은 구현 20줄 수준으로 단순하게 한다.

| 상자 | 다음 복습 간격 | 의미 |
|---|---|---|
| 0 | — | 미시도(복습 대상 아님) |
| 1 | 1일 | 방금 틀렸거나 처음 맞힘 직후 |
| 2 | 3일 | |
| 3 | 7일 | |
| 4 | 없음(졸업) | 복습 큐에서 제외. 모의고사에는 포함 |

- 정답 → `box = min(box + 1, 4)`. 오답 → `box = 1`. 미시도 문제를 처음 맞히면 상자 2에서 시작(이미 아는 것을 1일 뒤 또 묻지 않는다), 처음 틀리면 상자 1.
- `due = 시도 시각 + 간격`(자정 기준으로 잘라 저장: `YYYY-MM-DD`). "오늘 복습" = `due <= 오늘` AND `box in 1..3`.
- 모의고사에서 푼 결과도 상자를 갱신한다(`source: "exam"`으로 기록만 구분).
- 복습 화면(`#/review`): 오늘 복습 n개 → [시작]. 세션은 퀴즈와 동일 UI, 출제 순서는 due 오래된 것부터, 상한 없음(보통 10~40개). 홈 대시보드에 "오늘 복습 n" 카드가 가장 위.
- 상한선: 하루에 새로 상자 1로 떨어지는 문제가 폭증해도 규칙은 그대로 두고, 대신 복습 화면에 "노드별로 나눠 풀기" 필터를 준다.

### 5-6. 모의고사 (`#/exam`)

- 설정: 문제 수 **20 / 40**, 범위 **전체 / 파트 / 챕터(다중 선택)**, 제한 시간 = 문제당 60초(20문제 = 20분, 끌 수 있음).
- 출제(`exam.buildExam(scope, n, seed)`): 범위 안 노드에서 **노드별로 고르게**(라운드 로빈으로 노드를 돌며 1개씩 무작위 추출, 상자 4 포함) 난이도 비율은 자연 분포. 결정적 재현을 위해 `seed`를 저장(리포트에서 "같은 문제로 다시" 가능).
- 진행: 채점을 즉시 하지 않는다. 답만 고르고 [다음]/[이전], 상단에 `7/20`과 남은 시간, 하단에 문제 번호 점 그리드(답한 것은 채움). 시간 종료 시 자동 제출. 이탈 방지: 진행 중 상태를 `sessionStorage`에 유지(새로고침 복구), `localStorage`에는 결과만.
- 결과 리포트(`#/exam/result/<examId>`): 총점, 소요 시간, **노드별 정답률 막대(약한 순 정렬)**, 약점 상위 3 노드에 [요약 카드 보기] [이 노드 퀴즈]. 문제별 검토(정답/내 답/해설 접기). 결과는 최근 20회 보관, 홈에 최근 점수 추이(텍스트 스파크라인 `▁▃▅▇`, 라이브러리 없음).

### 5-7. 용어 사전 (`#/glossary`)

- 데이터는 각 콘텐츠 파일의 `terms`가 레지스트리에서 병합된 결과(1절 규칙). 별도 중앙 파일 없음 — 콘텐츠 에이전트 간 조율 불필요.
- 화면: 상단 검색(한글·영문·id 부분 일치, 입력 즉시 필터), ㄱㄴㄷ/ABC 정렬 토글, 항목 = `한글 (영문)` + 정의 + 관련 노드 링크 + 관련 용어 링크.
- 해설 속 `[[term]]` 버튼을 탭하면 **바텀 시트(모바일)/팝오버(데스크톱)** 로 정의가 뜬다. 시트 안에 "사전에서 보기" 링크. `Esc`/바깥 탭으로 닫힘. 포커스는 열었던 버튼으로 복귀.
- 각 용어 항목에 [이 용어 관련 문제 n개] — `questions[].terms`의 역인덱스를 부팅 시 만든다.

### 5-8. 진도 저장 (`store.js`)

`safeStorage`(2048과 동일: `localStorage` 프로퍼티 접근 자체를 `try/catch`, 실패 시 메모리 폴백. 실패 시 설정 화면에 "이 브라우저에서는 진도가 저장되지 않습니다" 한 줄 표시 — 2048과 달리 여기서는 알려야 한다. 진도가 핵심 가치이고, 사용자가 내보내기로 대응할 수 있다).

키 2개, 값은 JSON 문자열:

```js
// "apps.ds-level2.progress.v1"
{
  version: 1,
  updatedAt: "2026-09-18T12:34:56.000Z",
  quiz: {                       // 문제별 기록. 시도한 문제만 존재
    "a-2-3-q07": { box: 2, due: "2026-09-21", last: true, correct: 3, wrong: 1, at: "2026-09-18T12:00:00Z" }
  },
  practice: {                   // 실습별 기록
    "a-2-3-p01": { solved: true, attempts: 2, at: "..." }
  },
  cards: { "a-2-3": "2026-09-17T09:00:00Z" },   // 요약 카드 열람 시각
  exams: [ { id: "x1726660000", at: "...", scope: ["a"], n: 20, seed: 8123, score: 15, byNode: { "a-1-1": [2, 3] } } ]  // 최근 20개. [정답, 출제]
}
// "apps.ds-level2.settings.v1"
{ version: 1, theme: "auto" | "light" | "dark", fontScale: 1 | 1.15, examTimer: true, showHintByDefault: false }
```

- 쓰기는 **변경 시 즉시**(문제 채점마다 한 번). 400문제라도 JSON은 수십 KB라 문제없다.
- 읽기 시 `version` 확인 → 미래에 `migrate(v)` 체인. 파싱 실패·형식 오류면 빈 진도로 시작하고 손상본을 `apps.ds-level2.progress.corrupt`에 옮겨 둔다(덮어쓰지 않는다).
- **내보내기/가져오기 — 넣는다.** 회사 PC ↔ 집 PC ↔ 폰 이동이 명시된 요구이고, `localStorage`는 오리진·기기별이다. 설정 화면에서 [JSON 내려받기](`ds-level2-progress-YYYYMMDD.json`, Blob) / [파일 선택] / **[붙여넣기 텍스트 상자]**(폰에서는 파일 다루기보다 메신저로 보낸 텍스트를 붙여넣는 편이 쉽다). 가져오기 기본은 **병합**: 문제·실습별로 `at`이 더 최신인 기록을 채택, exams는 id 기준 합집합. 체크박스 "기존 진도 덮어쓰기". 가져오기 전 현재 진도를 자동으로 `…progress.backup`에 복사.
- [진도 초기화]는 인라인 2단계 확인(버튼 라벨 변경 방식, `confirm()` 금지 — iframe에서 부모까지 블로킹).

## 6. 실습 ↔ Jupyter 연동

앱은 Python을 실행하지 않는다. 사용자는 개인 데스크톱 Jupyter Notebook에서 셀을 실행하고 **값만 앱에 입력**한다.

## 7. 화면 구성

**결정: 단일 페이지 + 해시 라우팅.** 다중 HTML이면 데이터 파일 11개를 페이지마다 다시 로드하고, 상태(퀴즈 세션·타이머)가 페이지 전환에 날아간다. `file://`에서도 해시는 문제없다.

라우트 표:

| 해시 | 화면 |
|---|---|
| `#/` | 홈(대시보드) |
| `#/tree` | 커리큘럼 트리 |
| `#/topic/:id` , `#/topic/:id/card|quiz|lab` | 토픽 학습(탭). check 노드는 `quiz`만 |
| `#/wrong` | 오답 노트 |
| `#/review` | 오늘 복습 |
| `#/exam` , `#/exam/run` , `#/exam/result/:examId` | 모의고사 설정/진행/결과 |
| `#/glossary` , `#/glossary/:termId` | 용어 사전 |
| `#/settings` | 설정(테마·글자 크기·내보내기/가져오기·초기화·데이터 경고) |

라우터는 `hashchange`로 뷰 함수를 호출하고, `<main id="view">`의 내용을 교체한다. 뷰마다 스크롤 위치를 `sessionStorage`에 저장·복원. 잘못된 id는 홈으로 보내며 토스트.

### 오답 노트 / 복습 / 모의고사 / 사전 / 설정
5절의 설명대로. 모의고사 진행 화면은 문제 하나 + 하단 `[이전] [번호 그리드] [다음]` + 상단 타이머. 설정은 항목 목록(테마 3택, 글자 크기 2택, 타이머 on/off, 내보내기/가져오기 블록, 초기화, 데이터 경고 n건 보기, 버전).

### 임베드(iframe) 모드

블로그 카드의 iframe은 약 320×427px로 작다. 앱이 `window.self !== window.top` 이거나 `?embed=1`이면 `html[data-embed]`를 붙인다.
- 홈만 **컴팩트 대시보드**로 바뀐다: 진도 링 + "이어서 학습" + 오늘 복습 수 + 최근 점수 한 줄 + **[전체 화면으로 열기 ↗]**(`target="_top"`, 현재 해시 유지). 다른 라우트도 동작은 하지만 탭바 대신 상단 햄버거 메뉴.
- 임베드 모드에서는 `autofocus` 금지, 부모 스크롤을 뺏는 `scrollIntoView` 금지.
- Embed 단계 참고 마크업: `<iframe src="apps/ds-level2/index.html?embed=1" title="데이터 사이언스 레벨2 학습앱" loading="lazy">`.

### 스타일 톤

자체 `style.css`에 토큰을 **복제**한다(블로그 `css/tokens.css`를 링크하지 않는다 — 자체 완결). 값은 블로그와 맞춘다: 배경 `#fcfcfd`/다크 `#121417`, 글자 `#16181d`/`#e6e8ec`, 강조 `#2b52c9`/`#8aabff`, 테두리 `#e6e8ec`/`#262a30`, 반경 6px, 같은 `font-sans`/`font-mono` 스택. 추가로 상태색(정답 초록·오답 빨강·경고 주황)은 배경 대비 4.5:1 이상으로 두 테마 각각 정한다. 코드 토큰색 5개도 두 테마용.

## 8. 접근성·UX 세부

- **보기 선택 키보드**: mcq는 `1`~`4`(보기 5개면 `5`), ox는 `o`/`x`(및 `1`/`2`), `Enter` = 정답 확인 → 공개 후 `Enter` = 다음. `short`는 입력창에 포커스, `Enter` = 확인. 키 처리는 퀴즈 컨테이너에 `keydown`으로 붙이고 입력창 안에서는 숫자키를 가로채지 않는다.
- **정답 공개 전**: 보기는 `role="radiogroup"` 안의 `<button role="radio" aria-checked>`; 선택 전엔 [정답 확인] `disabled`. **공개 후**: 정답 보기에 `data-state="correct"`, 내가 고른 오답에 `data-state="wrong"`, 나머지 `disabled`; 색 외에 ✔/✘ 아이콘과 `aria-label` 텍스트("정답", "내가 고른 오답"); 해설 영역이 나타나고 **포커스는 [다음] 버튼으로**; 라이브 영역(`role="status"`)에 "정답입니다 / 오답입니다. 정답은 ②".
- **해설의 용어 링크**: `<button class="term">`, 밑줄 점선. 탭 → 바텀 시트(`role="dialog" aria-modal`), 닫으면 포커스 복귀. 해설 하단에 `terms[]` 칩 자동 표시(본문에 `[[ ]]`를 안 썼어도 연결).
- **코드 블록**: `<pre>`에 `overflow-x: auto; -webkit-overflow-scrolling: touch;`, 줄바꿈 금지, 글자 `0.85rem` 모노, 탭 4칸. 코드 블록 우상단 [복사]. 폰 세로 화면에서 긴 줄은 가로 스크롤(자동 줄바꿈은 코드 의미를 깨므로 안 한다). 코드 블록 자체는 `tabindex="0"`으로 키보드 스크롤 가능.
- **긴 해설 접기**: 해설이 8줄(약 480px)을 넘으면 `max-height` + 그라데이션 + [더 보기]. 오답 문제는 접지 않고 전부 펼친다(읽어야 하는 순간이므로).
- **다크 모드 — 결정**: 블로그의 `localStorage["theme"]` 키를 **읽지 않는다**(암묵적 계약 의존, 2048과 같은 이유). 자체 규칙: 설정값 `theme: auto|light|dark`(기본 `auto` = `prefers-color-scheme`), 부팅 시 `<head>` 인라인 스크립트로 `html[data-theme]`를 즉시 세팅해 FOUC 방지(블로그와 같은 **메커니즘**은 따른다: `html[data-theme]` + `prefers-color-scheme`), 상단바 토글 버튼, `?theme=light|dark` 쿼리로 Embed 단계에서 강제 가능. 앱 내 토글이 필요한 이유: 지하철 야간에 폰으로 쓰는 시나리오.
- 글자 크기 옵션(설정: 보통/크게 = `html { font-size: 100% | 115% }`).
- `prefers-reduced-motion`이면 전환·시트 애니메이션 제거. `user-scalable=no` 금지. `lang="ko"`. 모든 아이콘 버튼에 `aria-label`. 포커스 링 `:focus-visible` 2px.
- 타이머는 `aria-live`로 매초 읽지 않는다 — 5분·1분 남았을 때만 알림.
- 오프라인: 모든 파일이 로컬이라 한 번 열리면 네트워크 없이 동작(서비스 워커는 두지 않는다 — `file://`에서 등록 불가·복잡도 대비 이득 낮음. 폰에서는 GitHub Pages 주소를 홈 화면에 추가하면 캐시로 충분).

## 9. Build 단계 작업 분할 계획

**12개 서브에이전트: 엔진 1 + 콘텐츠 11.** 동시 실행이 어려우면 콘텐츠를 파트A 6개 → 파트B 5개 두 파도로 나눈다. 엔진은 첫 파도와 같이 시작한다.

### 왜 스키마를 먼저 고정하는가
엔진과 콘텐츠가 만나는 지점은 3절의 스키마와 1절의 `DS2.register()` 계약뿐이다. 이 문서가 그 계약이므로 **Build 시작 전에 사용자 승인으로 3절을 동결**하고, Build 중에는 어느 에이전트도 스키마를 바꾸지 않는다(필드가 더 필요하면 `tags`/`note` 같은 선택 필드만 추가, 기존 필드 의미는 불변). 그래야 콘텐츠 11명이 엔진을 기다리지 않고, 엔진도 콘텐츠 없이 **더미 노드 1개**(`data/_sample.js`, 완성 후 삭제)로 개발할 수 있다.

### 엔진 에이전트 (1명)
- 파일: `index.html`, `style.css`, `js/*` 전부, `tools/validate.js`, `tools/validate.html`, `tools/extract_practice.js`, `tools/verify_practice.py`.
- 순서: ① `registry.js`+`curriculum.js`+더미 데이터 → ② `store.js`·`grader.js`·`leitner.js`·`exam.js` 순수 함수(콘솔 테스트: `window.__DS2 = { grader, leitner, exam, ipynb }` 디버그 노출) → ③ 라우터·뷰 골격·CSS → ④ 퀴즈 세션·실습 탭·ipynb → ⑤ 오답·복습·모의고사·사전·설정·내보내기 → ⑥ 임베드 모드·다크·접근성 → ⑦ `tools/` 검증기.
- 검증기(`tools/validate.js`)는 콘텐츠 에이전트가 **작업 중 자기 파일에 실행**할 수 있어야 하므로 엔진 작업 중 **가장 먼저 완성해 공유**한다(반나절 안). Node 실행: `node tools/validate.js data/a1-sql.js` → `vm.runInNewContext`로 `registry.js`·`curriculum.js`·대상 파일을 로드하고 검사 결과를 표준 출력. 브라우저 실행: `tools/validate.html` 열기.

### 콘텐츠 에이전트 (11명) — 각자 받는 것
- 자기 파일 1개(4절 표의 행), 이 spec의 2·3·4절, 담당 노드 id 목록, 할당량(문제 수·난이도·유형 분포), 용어 최소 수.
- 규칙: 자기 파일 외 수정 금지. `DS2.register()` 한 번만 호출. 백틱 문자열 금지. 태그한 용어는 자기 파일에서 정의. 정답 인덱스 분산. 해설 5조건(3-3). 시험 지문 스타일(전문용어 한글+영문).
- **실습 정답은 반드시 Python으로 실제 실행해 검증한다.** 절차: 데이터 파일 작성 → `node tools/extract_practice.js data/<파일>.js > /tmp/p.json` → `python3 tools/verify_practice.py /tmp/p.json`(각 과제의 `setup` + `solution`을 새 네임스페이스에서 `exec`, 마지막 표현식 값을 `answer` 규칙으로 비교, 통과/실패/예외 표) → 전부 통과 시 `verified: { by: "python", at, env }` 기입. 실패한 값은 코드를 고치거나 정답을 재계산.
- **검증 환경**: 작업 컨테이너에 Python 3.11 + numpy, pandas 3.0.6, scikit-learn 1.9.1, scipy 1.17.1, statsmodels 0.15.0이 설치되어 있다(`pip install --user`). 만약 새 세션에서 설치가 안 되어 있으면 같은 명령으로 재설치한다. 그래도 실패하면: ① SQL 실습(`sqlite3`)과 순수 Python 실습(파트B 1장)은 stdlib만으로 검증 가능하니 그것부터 검증. ② 나머지는 `verified: { by: "none", reason: "..." }`로 정직하게 표시하고, 정답 값을 **손으로 유도 가능한 형태**(정수 개수, 작은 표본에서 손계산 가능한 평균 등)로 설계해 손계산 근거를 `explanation`에 남긴다. ③ Review 단계에서 `verified.by !== "python"`인 과제를 목록화하여 사용자의 Jupyter에서 `tools/verify_practice.py`를 돌려 재검증하고 결과를 반영한다(앱 설정 화면에도 "미검증 실습 n개" 표시).

### 통합
콘텐츠 파일이 도착하는 대로 `index.html`의 `<script>` 목록은 처음부터 11개를 다 적어 두고(없는 파일은 404이지만 앱은 뜬다 — `registry`가 빈 노드를 "준비 중"으로 표시), `tools/validate.html`로 전체 검증 → 경고 0을 목표로 수정.
