## Build 이탈 사항 판정

1. **focus/blur 대신 focusin/focusout — 타당.** `focus`/`blur`는 버블링하지 않아 래퍼에 달면 자손 버튼 포커스를 못 본다. 실측: 게임 포커스 시 `data-focused=true`, 되돌리기/새 게임 버튼으로 포커스가 옮겨가도 유지, 게임 밖으로 나가면 해제 — 의도한 의미론과 정확히 일치.
2. **오버레이 표시를 render() 뒤로 이동 — 타당.** 오버레이 문구가 최종 점수를 읽고, 오버레이 아래 보드도 최종 상태여야 한다. 승리·게임 오버 동시 조건에서도 순서 문제 없음을 실측.
3. **max-height 480px 브레이크포인트 추가 — 타당.** spec이 "가로 모드에서 잘리지 않을 것"을 요구하는데 폭 기준 분기로는 높이 부족을 못 잡는다. 640×360 실측에서 이 분기 덕에 스크롤 없이 수납됨. CLAUDE.md의 "브레이크포인트는 구조가 바뀌는 지점에만"과도 부합(높이 부족은 구조가 바뀌는 지점이다).
4. **타일 팔레트를 고전보다 어둡게 — 타당.** 고전 2048 팔레트는 흰 글자 대비가 2:1 안팎으로 WCAG 미달. 실측 결과 전 타일 4.5:1 이상을 달성했으므로 spec의 대비 요구가 팔레트 변경을 강제한 것이 맞다.
5. **다크 팔레트 블록 중복 — 타당(필요악).** `prefers-color-scheme` 자동 대응과 `?theme=` 오버라이드를 모두 지원하려면 선택자가 두 개 필요한데, 순수 CSS에는 변수 묶음 재사용 문법이 없다. 두 블록 값 일치를 대조 확인했고, 소스에 "두 곳을 같이 고칠 것" 주석이 있다. CLAUDE.md의 "다크 색은 tokens.css에만" 규칙은 블로그 본체용이고, 자체 완결 원칙상 이 앱은 tokens.css를 참조할 수 없다.

## 검증하지 못한 것

1. **`file://` 직접 실행 (I절)** — 검증 환경의 브라우저 패널이 `file://` 문서를 정적 스냅샷으로만 렌더링해 JS 실행을 확인할 수 없었다. 구조상 근거(클래식 스크립트·상대 경로·fetch 없음)로는 동작해야 한다. **확인 방법: 탐색기에서 `apps\2048\index.html` 더블클릭 → 게임이 뜨고 방향키가 동작하면 통과.**
2. **iOS 실기기 제스처** — 당겨서 새로고침 미발동, 더블탭 확대 억제, 두 손가락 확대 허용은 에뮬레이션으로 완전히 재현되지 않는다. CSS 방어(`overscroll-behavior: contain`, `touch-action: manipulation`, `user-scalable=no` 미사용)는 모두 확인했다. **확인 방법: 아이폰 Safari에서 보드를 아래로 스와이프해 새로고침이 안 되는지, 핀치 확대가 되는지 확인.**
3. **스크린 리더 실낭독** — 라이브 영역 갱신은 DOM으로 확인했으나 실제 낭독은 NVDA/VoiceOver로만 확인 가능하다.
4. **샌드박스 iframe 렌더링** — `sandbox="allow-scripts"` iframe이 검증 패널에서 화면 합성이 되지 않아 시각 확인은 못 했다. 다만 동일 조건(스토리지 접근 예외)을 별도 페이지로 재현해 게임 정상 동작을 확인했으므로(E절) 기능상 공백은 없다.
