# 성장 빙고 — Review 결과

검증 기준은 승인된 `spec.md`. 검증은 Build 담당과 다른 담당이 했다. 테스트 스크립트와 스크린샷은 `/tmp`에만 두었다. 아래 "통과"는 내가 직접 돌려 본 것만 적었고, 못 본 것은 "확인 못 함"으로 적었다.

## 1. 결론

출시해도 된다. 규칙 계층, 판 데이터, 길잡이는 spec과 맞고 브라우저 흐름도 막힌 곳이 없었다. 다만 발견한 문제 4건(중간 1, 낮음 3)은 고쳤고 같은 방법으로 다시 확인했다. 남은 것은 설계 판단이 필요한 2건과 실기기에서만 볼 수 있는 항목이다.

- 가장 중요한 수정은 "대체 미션으로 인정" 표시가 칸 상세 시트에서 체크해도 저장되지 않던 버그다.
- 남은 문제 중 눈여겨볼 것은 주차 고정 기간 바로 다음 날(예: 11일차)에 칸이 "완성할 수 없음"으로 표시되지만, "어제 한 일"로는 기록할 수 있다는 점이다(spec 6-3절과 2-1절이 서로 어긋남).
- 길잡이 계산은 이 PC에서 20~40ms, CPU 4배 감속에서 90~120ms다. spec의 50ms 기준을 감속 환경에서는 넘는다.

| 3 | 낮음 | 레벨이 "확인 대기 때문에" 잠겼을 때 문구가 같은 말을 두 번 하고 부정확함 | 고침, 재확인함 |
| 4 | 낮음 | `print.html?start=2026-13-45`처럼 없는 날짜가 다른 날짜로 넘쳐 인쇄됨 | 고침, 재확인함 |

**문제 1. 대체 미션 표시가 사라짐 (중간)**
- 재현: 체력 칸(예: 시작 기록)을 [했어요] → 가족 모드 → [오늘] 탭에서 그 칸의 이름을 눌러 상세 시트를 연다. 이때 대기 목록(탭 화면)과 시트 양쪽에 같은 스티커의 "대체 미션" 상자가 있다. 시트의 상자를 체크하고 시트의 [도장]을 누르면 `alt`가 `false`로 저장된다.
- 원인: `doStamp`가 `document.querySelector('[data-alt="id"]')`로 첫 번째 상자만 읽었다. 문서 순서상 탭 화면의 상자(체크 안 됨)가 먼저 잡혔다.
- 고친 내용: `app.js`의 `stamp` 처리가 눌린 [도장] 버튼이 든 줄(`.srow`) 안의 상자만 읽도록 바꿨다. `doStamp(id, alt)`로 값을 넘긴다.
- 재확인: 같은 시나리오를 다시 돌려 `F-W1:1:confirmed:alt`로 저장됨. 탭 화면에서 체크하고 탭 화면에서 도장을 찍는 경우, 시트에서 체크하는 경우(탭 화면 상자가 같이 있는 경우와 없는 경우) 모두 `alt: true`.

**문제 2. 같은 초 안의 두 탭 저장 경쟁 (낮음)**
- 재현: `storage` 이벤트가 전달되지 않는 상태(스크립트로 이벤트를 막음)에서 탭 A가 기록한 뒤 1초 안에 탭 B가 다른 칸을 기록하면 저장값에 B의 기록만 남는다.
- 원인: 저장 직전에 "다른 탭이 먼저 썼는가"를 `updatedAt`으로 비교하는데, 이 값이 초 단위(`nowIso()`)라 같은 초면 서로 같은 값으로 보였다.
- 고친 내용: `persist()`가 `updatedAt`에 밀리초가 든 `toISOString()` 값을 쓴다. 이 값은 비교용 표지로만 쓰이고 화면에 나오지 않는다.
- 재확인: 같은 시나리오에서 저장값이 `['E-READ-A', 'A-AUTO']`로 둘 다 남음. 이벤트가 정상 전달되는 일반 경우(두 탭이 서로 따라 바뀜)도 다시 확인함. 다만 Build 담당이 말한 "두 탭 동시 사용"의 실제 경쟁은 두 탭이 같은 밀리초에 쓰는 경우까지 막는 것은 아니다(그런 일은 사실상 없다고 본다).

**문제 3. 레벨 잠김 문구 (낮음)**
- 재현: `E-LV1` 확정 1 + 대기 1인 상태에서 `E-LV2` 상세를 연다. 이전 문구는 "…의 도장을 다 받으면 열립니다. 가족 도장을 받으면 열립니다."로 같은 말을 반복했다.
- 고친 내용: "…에 확인 대기 중인 스티커가 있습니다(지금 1개 확정, 1개 확인 대기). 가족 도장을 받으면 열립니다."
- 재확인: 같은 상태를 다시 열어 새 문구를 직접 봄. 대기가 원인이 아닌 경우의 문구(미니 프로젝트 ③이 ②에 막힌 경우)는 그대로임을 확인.

**문제 4. 인쇄 시작일 검증 (낮음)**
- 재현: `print.html?start=2026-13-45` → 시작일 2027년 2월 14일로 인쇄.
- 고친 내용: `print.js`가 날짜를 되돌려 보아 같은 날인지 확인하고, 아니면 시작일 없이 인쇄한다.
- 재확인: 잘못된 날짜는 시작일 칸이 비고, `?start=2026-12-01&detail=1`은 이전처럼 날짜와 3장이 나옴.

고친 뒤 `balance.test.js`(26개)와 `rules.test.js`(54개)를 다시 돌려 통과했고, 도장·초기화·가져오기·두 탭 시나리오를 다시 돌려 이상이 없었다.

## 4. 남은 문제

1. **주차 고정 기간 바로 다음 날의 표시와 기록 가능 여부가 어긋남 (중간, 설계 판단 필요).** 11일차에 `E-W1`이 비어 있으면 판은 "기간이 지나 완성할 수 없음"으로 흐리게 표시하고 길잡이는 이 칸이 든 줄을 뺀다(spec 6-3절, 테스트도 이 동작을 기대한다). 그런데 spec 2-1절·12절 때문에 "어제 한 일"로 10일차 기록은 아직 된다. 실제로 11일차에 10일차로 기록이 들어가고 칸이 완성된다(직접 확인함). 하루 동안은 살릴 수 있는 칸이 죽은 것으로 보인다. 고치려면 spec 6-3절의 기준을 바꾸거나("기간 끝 + 어제 한 일 허용 1일") 어제 한 일을 이 칸에서는 막아야 한다. 어느 쪽인지 정해야 해서 건드리지 않았다.
2. **길잡이 계산 시간 (낮음).** 일반 CPU에서는 20~40ms지만 4배 감속에서 87~118ms이고, 화면을 그릴 때 두 기준(적게/빨리)을 둘 다 계산해 186ms까지 간다. spec은 50ms를 넘으면 `requestIdleCallback`으로 미루라고 했다. 이 PC에서 4배 감속은 실기기 대용일 뿐이라 실제 휴대폰 값은 모른다. 두 기준을 한 번에 계산하면 절반으로 줄일 수 있을 것으로 보이나 `guide.js`를 크게 건드려야 해서 하지 않았다.
3. **임베드 미니 판이 확인 대기를 칸에 표시하지 않음 (낮음).** 대기 수는 아래 글자("확인 대기 1")로만 보인다. spec 10절은 "채움 정도만"이라 어긋나지는 않는다.
4. **시작일을 앞당기면 그날 확인 대기가 만료됨 (낮음).** 오늘 일차가 점프하기 때문에 spec 7절의 "미래로 건너뛴 경우"와 같은 처리가 된다(직접 확인함: 5일차 대기 스티커가 10일차가 되면서 사라짐). 시작일 변경 확인 문구에는 이 점이 없다.
5. **안내 띠가 쌓임 (낮음).** 가져오기 오류를 연달아 내면 지난 안내가 닫히지 않고 위로 쌓인다.
6. **자정 직후 첫 조작 때는 "날짜가 바뀌었습니다" 알림이 없음 (낮음).** 첫 조작 직전에 날짜를 다시 계산해 새 일차로 정확히 기록되지만(확인함), 그 경로에서는 `announce`를 부르지 않는다. 포커스·화면 복귀·60초 타이머로 바뀔 때는 알린다.
7. **줄 머리표 16개가 Tab 정지점이다 (낮음).** 판 안으로 들어가는 데 Tab 13번이 든다. spec 13절이 줄 머리표를 버튼으로 정해서 따랐다.

## 5. spec과 다른 점

- `family-gate.js`가 밖에 내놓는 것이 spec 11절의 3개(`currentActor`, `requestVerifier`, `lock`)보다 많다(`init`, `isUnlocked`, `isConfigured`, `onChange`, `renderSetup`, `renderManage`, `IDLE_LOCK_MS`). 파일 머리 주석에 이유(비밀번호 방식의 설정 화면이 한 벌)를 적어 두었고 `app.js`는 비밀번호 값을 읽지 않으므로 이식에 지장은 없다고 판단했다. 다만 이식할 때 갈아 끼울 범위는 spec 표보다 조금 넓다.
- spec 3-4절의 "프로젝트 LV1은 모든 조합(100%)에 필요"는 틀렸다. 가로3·4·6 + 세로2·5·7 + 대각 ↙ 조합 하나(스티커 92개)는 미니 프로젝트 칸을 하나도 포함하지 않아 LV1이 필요 없다. 실제는 11,440개 중 11,439개이고, Build 담당이 테스트 기대값을 실제에 맞춘 것이 옳다. 별도 스크립트로 확인했다. spec 문구는 내가 고칠 수 없다.
- 인쇄 판 네모를 7mm에서 6mm로 줄였다(Build 담당 보고). 인쇄 PDF 1쪽에 판이 들어가는 것은 확인했지만 6mm 네모에 스티커를 실제로 붙일 수 있는지는 종이로 확인하지 못했다.
- `updatedAt` 형식이 spec 8-1절 예시(`+09:00`)와 달리 UTC `toISOString()`이다(문제 2의 수정). 다른 곳에서 파싱하지 않는 비교용 표지다.
- 주차 고정 칸의 `estimateFinish`는 `own = max(own, 기간 시작 + 남은 수 − 1)`로 구현되어 있다. spec은 `기간 시작 일차`만 쓴다. 주차 고정 칸이 모두 네모 1개라 결과는 같다(전수 대조에서 차이 0건).

## 6. 실기기에서 사용자가 확인할 것

- 실제 휴대폰에서 7×7 판의 글자(축약 이름 4자)가 잘리지 않는지, 폭 320~360px에서 38~44px짜리 칸을 손가락으로 누르기 편한지. 화면 캡처로는 글자가 들어가는 것만 봤다.
- iOS 사파리: 아래 탭바가 홈 표시줄에 가려지지 않는지(`safe-area-inset-bottom`은 CSS에 있으나 확인 못 함), 두 손가락 확대, 사파리 개인 정보 보호 모드에서 저장 막힘 띠, 숫자판에서 숫자 키보드가 뜨는지.
- 실제 휴대폰에서 길잡이를 쓸 때 체감 지연(위 4절 2번).
- 가족 모드가 3분 뒤와 탭 전환 시 잠기는지. 코드는 있으나 타이머를 기다려 보지 않았고 탭 전환도 시험하지 않았다. **확인 못 함.**
- 인쇄: 사파리·크롬 인쇄 미리 보기, 흑백 인쇄에서 영역이 글자·무늬로 구분되는지(컬러 PDF만 봤다), 6mm 네모에 스티커 붙이기.
- 화면 읽기 프로그램(VoiceOver, TalkBack)으로 칸 이름과 상태 안내가 읽히는지. 코드의 `aria-label`·`aria-live`는 읽었으나 실제로 들어 보지 못했다. **확인 못 함.**
- `prefers-reduced-motion`에서 애니메이션이 꺼지는지(CSS 규칙이 있는 것만 봄). 흑백 필터로 영역·스티커 구분. **확인 못 함.**
- 블로그 메인에 카드를 붙인 뒤 실제 iframe 안에서의 모양(Embed 단계). 부모 페이지를 흉내 낸 임시 페이지에서만 확인했다.
- 서머타임이 끝나는(시계를 늦추는) 주의 일차 계산. 봄 전환(뉴욕 3월 8일)만 확인했다.

## 7. Review 이후 조치 (메인 세션)

Review 담당이 "설계 판단 필요"로 남긴 중간 심각도 문제 1건을 메인 세션에서 정리했다.

**문제.** 주차 고정 기간이 끝난 바로 다음 날(예: 11일차) 칸이 "완성할 수 없음"으로 표시되고 길잡이도 그 줄을 뺐다. 그런데 규칙 5번("어제 한 일" 기록 허용)에 따라 그날은 아직 전날 것으로 기록할 수 있었다. spec 6-3절과 2-1절이 어긋난 것이 원인이다.

**판단.** 사용자가 읽는 규칙(2절)을 기준으로 삼았다. 아직 채울 수 있는 칸에 ×를 띄우는 쪽이 더 해롭다.

**고친 내용.**

- `js/rules.js` `isCellDead`: 주차 고정 칸은 `오늘 > 기간 끝 + BACKDATE_DAYS`일 때 죽은 칸으로 본다.
- `js/app.js`: 기간 끝 다음 날 "오늘" 기준으로 열면 "[어제 한 일 기록]으로 바꾸면 오늘까지 기록할 수 있다"고 안내한다.
- `tests/rules.test.js`: 경계 기대값을 11일차 → 12일차, 25일차 → 26일차로 옮기고 11일차·25일차가 살아 있음을 추가로 단언한다.
- `spec.md` 6-3절과 15절 체크리스트 두 줄을 같은 내용으로 정정했다.

**재확인.**

- `node tests/rules.test.js` 54개 통과, `node tests/balance.test.js` 26개 통과.
- 브라우저(390px): 11일차에 기준 녹음 칸이 죽은 칸으로 표시되지 않고, 안내 문구가 나오며, "어제 한 일 기록"으로 10일차 스티커가 확인 대기로 들어간다. 12일차에는 "했어요"가 비활성이고 "기간이 지났습니다"가 나온다. 콘솔 오류 0건.

**그대로 둔 것.** `review.md` 4절의 낮음 4건(임베드 미니 판의 확인 대기 표시, 시작일 앞당기기 안내 문구, 가져오기 오류 띠 누적, 자정 직후 알림)과 저사양 기기의 길잡이 계산 시간은 고치지 않았다.
