# Review 지침 — MedReader 6단계 (6a + 6b)

너는 **Review** 서브에이전트다. Build 를 한 에이전트와 다른 에이전트다.
**코드를 고치는 것이 네 일이 아니다.** 근거를 들고 판정하는 것이 네 일이다.

## 검증 대상

- `6a` 커밋 `f5500ec` — 줄 bbox 공백 제외 + 페이지 클립, `algoVersion` 6→7
- `6b` 커밋 `f3f6f8c` — 원본 뷰 + 하이라이트 오버레이 + 표 크롭 폴백

두 커밋의 diff 를 봐라: `git show f5500ec`, `git show f3f6f8c`.

## 배경 — 반드시 알아야 할 것

- **곧 7000쪽 실제 자료로 교체된다**(형식 유사). 위험은 미지의 형식이 아니라 **10배 규모**다.
  메모리·DOM 개수·저장 용량을 그 기준으로 봐라. 특정 서적 튜닝은 지적하지 마라.
- **이 앱의 전제는 오프라인 읽기다.** 추출이 끝난 쪽은 pdf.js 없이 읽혀야 한다.
- 이 코드베이스가 반복해서 데인 것: **"각각은 맞는데 합치면 깨지는 두 규칙".**
  재개 모델에서 5건, 하이라이트 색에서 1건, bbox 에서 1건 나왔다. 그 눈으로 봐라.

## 특히 의심할 것 (전부 근거를 들고 답하라)

### 6a

1. **클립이 파이프라인에 새지 않았는가.** `buildPageLayout` 끝에서 클립하는데,
   그 앞에서 `line.bbox` 를 읽는 계산이 **정말 전부** 앞에 있는가?
   `blocks.js` 의 `columnMetrics`·`newParagraph`·`detectTables` 를 직접 읽고 확인하라.
   하나라도 클립 뒤에 있으면 레이아웃 판정이 조용히 바뀐다.
2. **`regions[].bbox`·`paragraphs[].bbox` 는 클립되지 않는다**(Build 가 보고함).
   6b 가 그것들을 그리는가? 그린다면 6a 가 반쪽짜리다.
3. **`stats.bboxDegenerate` 가 저장본에 남는가.** `store.js` 의 `stats` 화이트리스트를 봐라.
   7000쪽에서 이 수를 추적할 수 없다면 그게 문제인지 판정하라.
4. **`algoVersion` 7 의 파급.** 이미 추출된 문서가 전부 재추출된다.
   7000쪽에서 그 재추출이 어떻게 보이는가? 9-4 커서 재개가 그 경로를 타는가?

### 6b

5. **오버레이 정합** — `bbox` → 뷰포트 변환이 줌·회전에서 맞는가. 단위 테스트가
   **진짜 계산을 검증하는가, 스텁이 스스로를 확인하는가.** (과거에 이 함정에 빠진 적 있다.)
6. **7000쪽 규모** — 쪽을 넘길 때 canvas·`ImageBitmap`·크롭 캐시가 **정말 풀려나는가.**
   LRU 20 의 축출 경로에서 `ImageBitmap.close()` / canvas 해제가 빠져 있지 않은가.
7. **오프라인** — pdf.js 두 CDN 모두 실패했을 때 리플로우가 **정말** 계속 도는가.
   `original.js` import 자체가 `reader.js` 상단에 있다(정적 import). 그게 문제를 만드는가?
8. **표 안내가 낭독 큐에 들어간다**(Build 가 spec 과 다르게 한 곳으로 보고).
   `insertTableNotices` 가 `flowParas()` 결과를 바꾸는데, 그것이
   **5단계의 문장 단위 낭독·반복 재생·`markDone`** 과 충돌하지 않는가?
   특히 **구간 반복이 안내 문단을 포함하면** 어떻게 되는가.
9. **`pickAnchorLine`** — 사용자가 정한 정책과 구현이 일치하는가.
   정책: "듣는 곳과 보는 곳이 같으면 낭독 줄, 다르면 보고 있던 곳.
   `currentLineId`(보일 때) → `lastTappedLineId`(보일 때) → `viewportCenterLineId`
   → 보이는 첫 줄 → `null`". `tests/anchor.test.mjs` 가 이걸 실제로 고정하는가?
10. **spec 6-4 Android TTS 제약** — 뷰를 바꿔도 낭독이 끊기지 않는가.
    `renderPage()` 가 DOM 을 통째로 버리는데 `speaker` 의 세대 검사·utterance 참조가
    그걸 견디는가.

### 전반

11. CSS 물리속성 — `original.js`·`.hl-line` 예외 말고 0건인가(16-H).
12. i18n 4개 언어 키 집합이 같은가. **문구가 실제로 번역됐는가**(ko/fr 에 영어가 남아 있지 않은가).
13. 터치 타깃 48px(16-G), **375px 가로 넘침 0**.
14. `js/text/*` 순수성 — `document`/`window`/`fetch`/`indexedDB`/`navigator`/`localStorage` **0건**(16-A).
15. 서비스 계층이 UI 문자열을 만들지 않는가(3-2).

## 하지 말 것

- **코드를 고치지 마라.** 단, **명백한 결함이고 고치는 범위가 한 파일 안에서 닫히며
  기존 테스트가 전부 통과**하면 고쳐도 된다. 고쳤으면 보고서에 **무엇을 왜** 고쳤는지 적어라.
  판단이 서지 않으면 고치지 말고 근거와 함께 올려라.
- `spec.md`·`js/config.js` 의 `LAYOUT`·`KEEP_HYPHEN_*`(사용자가 채운 값)·`.nojekyll`·
  블로그 본체·`apps/2048/` 수정 금지. 커밋·푸시 금지.
- 취향 리팩터링·이름 변경·스타일 통일 금지.
- **원서 문장을 레포에 기록하지 마라.**

## 보고서

`apps/medreader/review.md` **끝에 6단계 절을 덧붙여라**(기존 내용을 지우지 마라).
반환값에도 요약을 담아라. **보고는 한국어로 쓴다.**

형식:
1. 판정 — 통과 / 조건부 통과 / 불통과. 차단·중간·경미·제안·이월 각 건수.
2. 위 15개 항목 각각에 대한 답과 **근거**(파일:줄, 실제 명령 출력, 측정값).
   추측으로 답하지 마라. 확인 못 한 항목은 "확인 못 함"이라고 정직하게 적어라.
3. 변이 테스트 결과 표 — 무엇을 망가뜨렸고 무엇이 빨개졌는가.
4. 고친 것이 있으면 무엇을 왜.
5. **7000쪽에서 터질 것** — 지금 729쪽에서는 안 보이지만 10배에서 문제가 될 것.
6. 사용자가 실기기(갤럭시 Z Fold 7)에서 확인해야 할 것 — 5줄 이내, 구체적으로.

**추측을 사실처럼 쓰지 마라.** 이 프로젝트에서 가장 비쌌던 실수가 그것이었다.
