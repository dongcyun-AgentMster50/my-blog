## 4. 사용자에게 물을 것 (3개)

1. **설명·요약을 앱 안에 넣을까?** (spec 17-2)
   - 가. 지금대로 후순위(NotebookLM 사용, 한도 0) / **나. 설명 먼저, 부를 때만 — 권장** / 다. 설명+요약 함께 / 라. 자동 요약(비권장).
   - 한도 영향: 설명 1회 = 호출 1회 ≈ 낭독 번역 약 5,900자분. 하루 10번이면 CMDT 2026 약 13쪽분의 번역 한도를 쓴다.
   - 권장 이유: 핸즈프리로 쓰는 사람이 NotebookLM 으로 옮겨 가기 어렵다. 설명은 "지금 이 문장"이라 NotebookLM 의 전체 요약과 덜 겹친다. 요약은 한 단계 뒤(11b)에서 다시 본다.
2. **스캔본 OCR 방식** (spec 17-5)
   - **권장: (c) 스캔본 감지·안내를 14단계에 먼저 → 실제 스캔 자료가 있으면 (a) 브라우저 OCR(Tesseract.js 등)을 문서 단위로 켤 때만(15단계).** (b) Gemini 비전 OCR 은 쪽당 1회라 그 책의 호출이 두 배 넘게 늘어 넣지 않는다.
   - 그 전에: **Nour 가 말한 "스캔 자료"가 실제로 스캔본 PDF 인지 견본 1개**를 받아 `dev/profile.mjs` 로 "텍스트 0인 쪽" 비율을 재 보자.
3. **Nour 에게 확인할 사실 묶음** (한 번에 묻기 권장): (가) 새 휴대폰 모델(설정 → 휴대폰 정보 캡처), (나) 준비하는 국제 언어 시험 이름, (다) 이어폰 종류(유선/블루투스 — 9a 확인용). 권장: 7b 의 Nour 기기 실호출(16-D0) 때 같이 묻는다.

## 참고 — 지금 7b 코드와의 관계

- 지금 i18n 의 `ai.state.region`·`settings.ai.verify.region` 문구("이 지역에서는 … 쓸 수 없습니다. 키 문제가 아닙니다 …")는 VPN 을 언급하지 않아 새 경계(13절 "VPN")와 맞는다. 문구는 바꾸지 않았다(7b 진행 중). "네트워크 위치 때문일 수 있습니다"로 다듬을지는 선택 사항 — 필요하면 7b Review 뒤에.
- 8-4 의 `canSave:true` 근거 문장에 "대안 경로(VPN·다른 프로바이더)"라는 표현이 있다. 내부 근거라 사용자에게 보이지 않아 그대로 두었다.
