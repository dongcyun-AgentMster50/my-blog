# 8k(목소리 고르기 + O3 억양) Plan/Build 에 넣을 것 — Nour 실기기 진단(2026-10-21)

## 출처
Nour 가 Realme(Android, Chrome 143 Mobile)에서 `dev/voices.html`(8k-0)을 열어 본 화면 녹화(약 74초, 2026-10-21 받음). 소리는 분석하지 못했다(화면만). [결과 복사]·[en → ko → en 이어 말하기]는 누르지 않은 것으로 보인다.

## 화면에서 읽은 사실
| 언어 | Chrome 음성 목록 | 앱이 고른 음성(`pickVoice`) | 앱이 쓸 lang |
|---|---|---|---|
| 아랍어(ar) | **없음** | 없음 → voice 없이 | ar-SA(번역문 경로) |
| 영어(en) | 5개 | **en_AU(오스트레일리아)** | en-AU(원문 경로) |
| 프랑스어(fr) | 2개 | **fr_CA(캐나다)** | fr-CA |
| 한국어(ko) | 1개 | ko_KR | ko-KR |
- 전체 음성 92개, 모두 `localService true`, 음성 이름이 기기 언어(아랍어)로 표시된다. **`lang` 이 밑줄 꼴**(`en_AU`·`bs_BA_#Latn`·`zh_HK_#Hans` — 스크립트 꼬리표 `#Latn`·`#Hans` 포함). 앱 `voices.js` 는 `_`→`-` 로 바꾸지만 **`#Hans` 같은 꼬리표**는 남는다 — 억양 묶음(O3) 만들 때 처리 필요.
- **영어를 오스트레일리아 억양, 프랑스어를 캐나다 억양으로 읽고 있었다** — `pickVoice` 가 목록에서 그 언어의 첫 음성을 고르고(모두 localService), 목록이 알파벳 순이라 en_AU·fr_CA 가 먼저 온다. 휴대폰 설정 목소리와 다를 가능성이 크다 → **E1 (가) "휴대폰 설정 따름"(voice 지정 없이 lang 만)** 의 근거가 실물로 확인됨.
- **아랍어 음성이 Chrome 목록에 없다** — 그런데도 Nour 는 아랍어 낭독을 들어 왔다(8h 피드백) → 지금도 voice 없이 `ar-SA` 로 시스템 엔진에 맡기고 있다. 8k 에서 아랍어는 계속 "voice 없이".
- 여러 단추를 빠르게 누르면 `interrupted` 오류가 기록된다(정상 — 앞 발화가 끊김).

## 아직 모르는 것 (Nour 에게 다시 부탁)
1. 휴대폰 **설정 → 텍스트 음성 변환** 화면 캡처(기본 엔진·언어별 목소리).
2. 영어: [앱이 고른 음성] / [voice 없이 en] / [en-US] / [en-GB] 중 **휴대폰 목소리와 같은 것**과 **듣기 좋은 것**.
3. [en → ko → en 이어 말하기] 와 [en → en → en 기준] 을 눌러 **간격 숫자**, 그리고 [결과 복사] 텍스트.
