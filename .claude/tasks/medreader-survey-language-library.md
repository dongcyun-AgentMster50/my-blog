## 할 일
A. **목록**: `G:/01_Language` 아래 전체를 훑어 언어 폴더별 파일 수·확장자별 수·총 크기. PDF 가 아닌 것(mp3·epub·djvu·doc·이미지 등)은 **개수와 종류만** 센다(열지 않는다).
B. **PDF 하나하나 진단**(시간 상한: 파일당 60초, 전체 90분 — 넘으면 표본으로 줄이고 그 사실을 적는다):
   - 쪽 수·크기·만든 프로그램(Producer/Creator)·Tagged 여부·암호(열리지 않으면 "암호/손상"으로 적고 넘어감)
   - **글자 층**: O1 규칙(`apps/medreader/dev/measure-scan-o1.mjs` 의 판정 — 10–90% 구간 12쪽 표본, scan / notext / text)을 **그대로** 쓴다. 이미 OCR 된 스캔본(이미지 + 보이지 않는 글자)도 구분할 수 있으면 표시.
   - **글자 체계 비율**(표본 쪽의 글자): 라틴 · 한글 · 한자(CJK) · 가나(히라가나·가타카나) · 키릴 · 아랍 · 기타. 이것으로 "주 언어"와 **혼합**(예: 영+한, 일+한, 중+한, 서+한)을 판정. 라틴 안에서 스페인어(ñ·á·é·¿·¡ 등)와 영어를 구분할 수 있는 만큼.
   - **추출 품질**: 깨진 글자(U+FFFD, 사용자 영역 PUA U+E000–F8FF, 제어 문자, 한 글자씩 띄어진 글자 "H e l l o", 같은 글자 반복) 비율 — 특히 한글·일본어·중국어 PDF 는 글꼴 매핑(ToUnicode)이 없으면 글자가 깨진다.
   - **판형 신호**(표본 몇 쪽, 앱 레이아웃 `dev/measure-lib.mjs` 의 `pageLayout`): 단 수, 표 띠, 세로쓰기(일본어 tategaki — 글자 방향·회전) 흔적, 루비(후리가나·병음 — 작은 글자가 큰 글자 위에 붙음) 흔적, 빈칸 "____"·보기 번호가 많은 문제집 꼴.
C. **MedReader 지금 능력과 대조**(코드·spec 을 **읽기만**): 원문 언어로 고를 수 있는 언어 목록, 문장 나누기가 띄어쓰기 없는 중국어·일본어에서 되는지(`js/text/segment.js` 등), TTS 언어 태그(zh-CN·ja-JP·es-ES) 처리, 번역 프롬프트의 원문 언어 제한, 검색(17-8)의 접기 규칙이 CJK 에서 되는지, 8m(영한 혼합, spec 19-1-2)·8l(스캔본, spec 17-5-1) 설계가 다른 언어 쌍(일+한·중+한)에도 맞는지.
D. **필요한 기능 목록**: B 의 실물 근거(파일 수·쪽 수)와 C 의 빈칸을 묶어 기능 후보를 만든다. 예: 원문 언어 추가(zh·ja·es), CJK 문장 나누기, 세로쓰기, 루비 처리, 혼합 언어 쌍 확대, 스캔본 일괄 OCR 안내(언어별 tesseract 언어 데이터 `chi_sim`·`jpn`·`spa`), 문제집 빈칸 낭독 규칙 등. 각 후보에: 영향받는 파일·쪽 수, 크기 추정(작음/중간/큼), AI 무료 한도 영향, 이미 있는 단계(8l·8m·8k)와의 관계. **우선순위 제안**과 **운영자 결정이 필요한 것**(선택지·권장).
E. **OCR 대상 목록**: 스캔본만 모아 언어·쪽 수·크기 표 + PC 일괄 OCR 명령 초안(OCRmyPDF `--skip-text`, 언어 코드별, 출력은 원본 옆 `[OCR]` 이름 — **실행하지 말고 초안만**).
