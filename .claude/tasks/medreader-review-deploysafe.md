## 특히 볼 것
- **import map 이 정말 모든 경로를 덮는가**: 정적 import, 동적 `import()`(앱 내부 — `grep -rn "import(" js`), 워커(있다면), CSS. 표에 없는 앱 모듈 요청이 하나라도 나가는지 — 브라우저 네트워크 기록으로 쿼리 없는 `/apps/medreader/js/` 요청 0을 확인.
- **키 정규화**: 표의 키 `"./js/x.js"` 가 문서 기준 절대 URL 로 풀리고, `js/ui/a.js` 안의 `'../text/b.js'` 같은 상대 import 가 같은 절대 URL 로 풀려 표에 걸리는가 — 깊이가 다른 모듈 몇 개로 실제 확인.
- **혼합 상태 재현을 독립적으로**: 로컬 서버에서 (1) 옛 표 + 옛 파일, (2) 새 표 + 새 파일, (3) **옛 표 + 서버엔 새 파일만**(정적 서버는 쿼리를 무시하므로 옛 해시 URL 이 새 내용을 돌려준다 — Build 가 말한 한계) 각각에서 무엇이 보이는가. (3) 에서 빈 화면이 아니라 부팅 실패 안내가 뜨는가, 그리고 **재추출이 섞인 규칙으로 굳는 경우(최악)** 가 (3) 에서 여전히 가능한가 — 가능하면 어떤 조건에서, 얼마나 가능성이 있는가(옛 index.html 이 캐시에 있고 그 표의 모듈 URL 중 일부만 캐시에서 빠진 경우). 막을 추가 장치가 필요한지 의견(예: 부팅 때 index.html 의 판 해시와 실제 로드된 모듈의 판을 대조해 다르면 재추출을 시작하지 않기).
- **부팅 실패 안내**: 정상 부팅에서 깜빡임 0, 실패 시 표시, [다시 불러오기], 아랍어 먼저·`dir`, 48px, 20초 기준의 근거(느린 폰·7,000쪽 첫 부팅에서 오탐하지 않는가 — 부팅 완료 표시가 무거운 작업 **전에** 세워지는가).
- **[텍스트 다시 추출]**: 지우는 것 목록이 코드와 맞는가(쪽·문항·섹션·extraction·퀴즈 색인 — 빠진 파생 데이터는? 표 크롭 캐시는 Build 가 기록만 함), 사용자 데이터(원문 언어·마지막 쪽·번역 캐시) 유지, 추출 중 다시 누르기·다른 책 열기·낭독 중 누르기 같은 겹침. `<dialog>` 접근성(포커스·Esc).
- **stamp-importmap**: 생성기가 index.html 의 표시 구간 **밖을** 건드리지 않는가, CRLF/LF 보존, 두 번 돌려도 같은 결과(멱등), `--check` 가 실제로 어긋남을 잡는가.
- 회귀: 서재·리더·낭독·띠(8b)·원본·설정·퀴즈, 콘솔 0, 360px 가로 스크롤 0, 키 누출 0.
- 테스트 3번 이상 + 동시 실행. 변이 3개 이상 재현 + 새것 2개(예: 동적 import 하나를 표 밖 경로로, 부팅 완료 표시를 늦게 세우기). 적용 grep 확인 후, 스크래치패드 복사본으로 복원·cmp(`git checkout`·`restore`·`stash`·`rm -rf` 금지).
