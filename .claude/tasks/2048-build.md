# Build 지침 — 2048 게임

## 너의 역할

이 프로젝트의 **Build 단계** 담당이다. 승인된 설계 문서대로 2048 게임을 구현한다.

## 먼저 읽을 것

1. `D:\01_claude_my-blog\apps\2048\spec.md` — **승인된 설계 문서. 이것이 유일한 진실이다.**
2. `D:\01_claude_my-blog\CLAUDE.md` — 프로젝트 규칙

설계 문서를 처음부터 끝까지 읽어라. 특히 **3장(핵심 알고리즘)**, **4장(입력 처리)**, **10장(예상되는 함정)**은 그대로 따라야 한다.

## 수정 허용 범위 — 엄격히 지킬 것

**오직 이 세 파일만 생성한다.**

```
D:\01_claude_my-blog\apps\2048\index.html
D:\01_claude_my-blog\apps\2048\style.css
D:\01_claude_my-blog\apps\2048\game.js
```

**절대 하지 말 것:**

- 블로그 본체(`index.html`, `post.html`, `css/`, `js/`, `posts/`, `vendor/`)를 **읽는 것은 되지만 수정은 절대 금지**
- `apps/2048/spec.md` 수정 금지 (승인된 문서다)
- `apps/2048/review.md` 생성 금지 (**다음 단계인 Review 담당의 몫이다**)
- `CLAUDE.md`, `.gitignore`, `.nojekyll` 등 루트 파일 수정 금지
- git 커밋 금지 (Embed 단계에서 한다)

작업을 마친 뒤 `git status`로 위 세 파일 외에 아무것도 바뀌지 않았음을 확인하라.

## 반드시 지킬 구현 사항

설계 문서에 다 있지만, 틀리기 쉬운 것들을 다시 강조한다.

1. **이중 합치기 금지** — `collapse()`에서 합쳤으면 `i += 2`로 두 칸을 소비한다. `[2,2,4,0]`은 `[4,4,0,0]`이지 `[8,0,0,0]`이 아니다. 별도 플래그 배열을 쓰지 마라.

2. **무효 이동에 타일 생성 금지** — 격자가 실제로 변했을 때(`changed === true`)만 새 타일을 만든다. 이걸 빠뜨리면 벽에 대고 방향키를 누르는 것만으로 판이 채워져 죽는다.

3. **모바일 스와이프는 필수 기능이다** — Pointer Events로 구현하고, 설계 문서 4-4의 **4중 스크롤 방어**를 모두 적용하라. 하나라도 빠지면 스와이프할 때 페이지가 스크롤된다.

4. **iframe 포커스 처리** — `#game`에 `tabindex="0"`, `pointerdown` 시 포커스, 포커스 없을 때 안내 문구. `autofocus`는 쓰지 마라.

5. **`safeStorage`** — `window.localStorage` **프로퍼티 접근 자체**를 `try/catch`로 감싸라. 값 읽기만 감싸는 것으로는 부족하다.

6. **검증용 노출** — `window.__2048 = { collapse, lineIndices, getState }`를 두어라. Review 단계에서 콘솔로 순수 함수를 직접 시험한다. 디버그 전용이라는 주석을 달아라.

7. **의존성 0** — CDN을 포함해 어떤 외부 라이브러리도 쓰지 마라. 2048은 라이브러리 없이 충분하다.

## 스스로 검증할 것

구현을 마치기 전에 **네가 직접** 다음을 확인하라. Review 단계에 미루지 마라.

설계 문서 8장 A절의 9개 케이스를 `collapse()`에 넣어 결과가 표와 일치하는지 확인한다. Node.js로 함수만 떼어내 돌리거나, 임시 스크립트를 만들어 확인한 뒤 **그 임시 파일은 반드시 지워라.**

| 입력 | 기대 출력 |
|---|---|
| `[2,2,4,0]` | `[4,4,0,0]`, gained 4 |
| `[4,4,4,4]` | `[8,8,0,0]`, gained 16 |
| `[2,2,2,0]` | `[4,2,0,0]`, gained 4 |
| `[2,0,2,2]` | `[4,2,0,0]`, gained 4 |
| `[0,0,0,2]` | `[2,0,0,0]`, gained 0 |
| `[2,4,2,4]` | 변화 없음 |
| `[0,0,0,0]` | 변화 없음 |
| `[4,4,2,2]` | `[8,4,0,0]`, gained 12 |
| `[2,2,2,2]` | `[4,4,0,0]`, gained 8 |

**하나라도 어긋나면 고친 뒤 다시 확인하라.**

## 코드 품질

- 한국어 주석을 쓰되, 코드가 자명한 곳에는 달지 마라. **왜 그렇게 했는지**를 적어라(무엇을 하는지는 코드가 말한다).
- 설계 문서가 정한 함수 이름과 구조를 그대로 따르라. 임의로 바꾸지 마라.
- 파일 전체를 IIFE로 감싸 전역 오염을 막아라.

## 막히면

설계 문서와 실제 구현이 충돌하거나, 설계대로 하면 동작하지 않는 부분을 발견하면 **임의로 바꾸지 말고 보고하라.** 무엇이 왜 안 되는지 적어서 돌려줘라.
