## 할 일
1. F1–F12 각각: 단계 이름(19-1 이름 규칙, 기존 8l·8m 에 합치는 것은 합친다), 크기, 근거(파일·쪽 수), AI 한도 영향, 시작 조건.
2. **8l 갱신**: 깨짐 판정 갈래(U+FFFD·PUA·제어 문자·한 글자씩 띄어짐 비율 — 조사 보고서의 실측 문턱, 스피쿠스 21–25% 제어 문자), 안내 문구(깨짐은 `--force-ocr` 가 필요하다는 점은 가이드에만).
3. **8m 갱신**: 해커스 견본으로 시작 조건 충족. 견본 쪽 몇 개로 판별 규칙 재확인 지점(조사 원자료 활용 — 측정은 하지 않아도 됨, "Build 첫 단계에서 잴 것"으로).
4. **F4 스페인어**(es 오판 막기 + 원문 언어 es): 어느 단계에 넣을지(7c 표기 확인), 문장 경계 `¿`·`¡`.
5. **F5 문제집 꼴**(`(A)` 보기, `-------` 빈칸 낭독 규칙), **F6 `domain`**(번역 지시문 분기 — 프롬프트·캐시 키 영향), **F7 검색 CJK·조사**(8g 끝난 뒤 — 한국어 조사 문제는 지금 ko 원문에도 있음을 강조), F8–F12 는 조건부·보류로 짧게.
6. 19-1 순서 갱신안(19-1-2 순서 뒤에 이어서): 8g-2·3·4 → 8k → 8l(+깨짐) → 8m(일정 확정) → … 새 단계 자리.
7. **PC 일괄 OCR 절차**(F1): 운영자 가이드용 — 영어만(`-l eng --skip-text`), 영+한(`-l eng+kor`, `kor.traineddata` 필요), 깨짐(`--force-ocr -l eng+kor`), Tagged PDF, 결과 크기(×3 안팎 — Advanced Grammar 실측 56→183MB), 폰용 가벼운 판 옵션(`--oversample`·`--deskew` 없이).
8. 운영자 결정이 더 필요한 것만 선택지·권장으로.
