# Build 보고 — 공개 전 묶음 P2: CMDT 2026 러닝 헤드(쪽 머리말) 낭독

> Build 서브에이전트(P2), 2026-10-10. **커밋하지 않았다.** 원서 문장은 옮기지 않았다(진단 조각만, 책 이름 표지 `CMDT 2026` 은 판정 근거라서 그대로 적었다).

## 1. 원인 — 먼저 잰 것

도구: `apps/medreader/dev/probe-running-heads.mjs`(새로 만듦). "진짜 머리말"은 판정 규칙과 **따로** 정한다 — 쪽의 맨 윗줄 묶음(숫자 → `#` 정규화)이 두 쪽 떨어진 쪽(같은 면) 또는 바로 이웃 쪽의 맨 윗줄과 같으면 머리말. 이웃은 앱처럼 앞뒤 1쪽 저장본을 넘긴다.

CMDT 2026 표본 201쪽(50~1850, 9쪽 간격 — 7c Review 와 같은 표본), 진짜 머리말 줄 253개에서 4-7 header 조건별 통과 수:

| 조건 | 통과 | 실패 |
|---|---|---|
| 상단 8% 영역 | 253 | 0 |
| 길이 ≤ 80자 | 253 | 0 |
| **fontSize ≤ 1.1×Fm** | **4** | **249** |
| 증거: 이웃 반복 | **0** | 253 |
| 증거: 대문자 비율 ≥ 60% | 243 | 10 |
| 증거: `^(SECTION\|CHAPTER\|PART)` | 1 | 252 |

- **주원인은 글자 크기.** 머리말이 본문(9pt)보다 크다 — 10~12pt, Fm 의 1.33배(중앙), 최대 1.5배. 1.1×Fm 을 넘어 header 를 놓치고, 대부분 `fontSize ≥ 1.15×Fm` 으로 **heading**(낭독함)이 됐다.
- **보조 원인은 이웃 반복 0.** 짝·홀 쪽 머리말이 다르다(짝: `N CMDT 2026 CHAPTER k`, 홀: `장 제목 CMDT 2026 N`). 앱은 앞뒤 1쪽만 이웃으로 받으므로 글자가 겹치지 않는다. 대문자 비율이 못 받는 10줄은 대소문자가 섞여 보이는 `… Chapter k` 꼴이었다(이 책 작은 대문자 글꼴이 소문자로 추출된다).
- 머리말 아래 간격은 최소 **2.64×Lm**(중앙 2.75). 머리말 없는 Harrison 의 맨 윗줄은 중앙 1.0×Lm(본문 행간).
- 덤으로 드러난 **기존 오판**: 띠 없이 "상단 8% 영역 안"만 보던 규칙이 영역 안 **본문**을 머리말로 빼고 있었다 — CMDT 표본 16줄(참고문헌 `[PMID …]` 줄, 표 머리), **Harrison 전수 27줄**(문항 라벨 `I-61.`·`V-57.`, `EXCEPT:`, 본문 문장 1줄, 그림 글자 등). CMDT 2026 은 상단 8%(57.6pt) 안에 본문이 3~4줄 들어온다.

## 2. 고친 규칙 (spec 4-7 header 행) — `js/text/blocks.js`, 상수는 `config.js` LAYOUT

```
header = 상단 8% ∧ 길이 ≤ 80 ∧ [머리말 띠 안]
       ∧ (쪽 번호 진행 ∨ fontSize ≤ HEADER_FONT_RATIO×Fm)
       ∧ (이웃 반복 ∨ 쪽 번호 진행 ∨ 대문자 ≥ 60% ∨ 접두)
```

1. **머리말 띠**(`topBand`, 새 조건): 줄이 쪽의 맨 윗줄 묶음(최고 baseline 에서 `HEADER_ROW_TOL_FACTOR`×Fm=0.5 이내)에 있고, 그 묶음과 아래 첫 줄의 간격이 `HEADER_BAND_GAP_FACTOR`×Lm(=1.5, heading 규칙의 "위 여백 ≥1.5×Lm"과 같은 값) 이상. 러닝 헤드는 본문 덩어리 **위 여백**에 있다는 구조 신호 — 영역 안 본문을 거른다.
2. **글자 크기 상한 1.1 → 1.6**(`HEADER_FONT_RATIO`). 띠가 본문을 거르므로 상한은 쪽 맨 위의 큰 표제(장 첫 쪽 제목, Harrison 2.8×Fm)만 막으면 된다.
3. **쪽 번호 진행**(`bandFolioRun`, 새 반복 신호): 이 쪽 띠 줄의 끝 숫자 n 과 **같은 자리**(쪽 위에서 잰 거리 ±0.5×Fm)의 이웃 띠 줄 끝 숫자 m 이 `n − m = 이 쪽 − 이웃 쪽`. 짝·홀 머리말이 달라도 쪽 번호는 1씩 나아간다. 맞으면 같은 띠의 모든 줄(쪼개진 홀수 쪽 "장 제목 | 책 이름 쪽번호")이 머리말이고, 글자 크기 상한도 보지 않는다 — 표가 많은 쪽은 Fm 이 작아 같은 12pt 머리말이 1.62~1.84×Fm 이 되어 전수에서 3쪽이 남았다.
   - "같은 자리"만으로는 안 된다(**처음에 그렇게 했다가 실측으로 버렸다**): 머리말 없는 Harrison 에서 그림·표가 쪽 맨 위에 오면 맨 윗줄도 띠가 되고 이웃 쪽 같은 높이와 겹쳐, 표 제목 1줄·그림 글자 1줄이 **새로** 머리말로 빠졌다. 쪽 번호 진행을 요구하자 0.
   - 끝 숫자만 본다(`TABLE II-11 …` 처럼 가운데 번호는 쪽 번호가 아니다).
4. 꼬리말·쪽번호·heading·표·문단 규칙은 그대로다. 이웃 반복(원래 4-7 규칙)도 그대로 증거로 남는다.

특정 책 값이 아니다: 띠(머리말은 위 여백에 있다)·쪽 번호 진행(머리말에는 쪽 번호가 있고 1씩 나아간다)은 조판 일반의 구조이고, 두 상수는 기존 4-7 의 "1.5×Lm"·행 허용폭과 같은 성격이다.

**spec 갱신 제안(오케스트레이터 몫 — 내 범위 밖이라 spec.md 는 손대지 않았다)**: 4-7 표 header 행을 위 식으로, 2-4 `BOOK_PROFILE` 표의 "박힌 값" 목록에 영어 고정 접두 정규식이 여전히 남아 있음을 유지.

## 8. 한계·남은 것

- **글자도 다르고 대문자도 아니고 쪽 번호도 없는** 짝·홀 머리말(예: 쪽 번호가 아래에 있는 책의 대소문자 장 제목)은 여전히 못 잡는다. 앞뒤 **2쪽**을 이웃으로 받으면(spec 4-7 원문 "최대 2페이지") 같은 면끼리 글자 반복으로 잡힌다 — `extract.js._neighborLayouts` 는 지금 ±1 만 넘긴다(P1 파일이라 손대지 않았다). 지금 세 책에서는 해당 없음.
- 첫 추출 때 이웃이 아직 없으면 쪽 번호 진행이 없다 → CMDT 의 대소문자 머리말(전체의 약 4%)은 이웃이 생긴 뒤 4-7 역할 재계산(`roleVersion`)에서 빠진다. 기존 경로 그대로.
- 접두 정규식 `^(SECTION|CHAPTER|PART)` 는 영어 고정 그대로(2-4 프로파일 몫).
- 측정 도구 자체의 한계: 정답 정의가 장 경계·앞부분 머리말을 놓친다(그래서 "머리말 아닌 header"에 실제 머리말이 섞여 있다 — 조각을 사람이 봤다).
