# Build 지침 — MedReader 6a단계: 줄 bbox 를 페이지 안으로 되돌린다

## 왜 지금 하는가

6b(원본 뷰)의 하이라이트 오버레이는 줄 `bbox` 를 **직접 그린다.** 지금 그 값의 4.39%가
페이지 밖으로 나간다. 지금 고치지 않으면 6b 가 만들어지는 날 처음 눈에 보인다.

**이 결함의 원인은 하나가 아니라 셋이다.** `review.md` ⑥ 항목은 그중 하나만 적었고,
한때 "회전된 줄 문제"로도 불렸으나 **아니다**(`normalizeItems` 가 회전 아이템을
`rotated[]` 로 분리해 `lineBBox` 까지 오지 않는다). **spec 4-6 의 `[수정 2026-09-23 — 6a]`
표를 먼저 읽어라.** 오케스트레이터가 실측해 spec 에 박아 넣었다.

## 실측 요약 (729쪽 중 365쪽, 줄 24,460개 — 재측정 불필요)

| 원인 | 줄 수 | 초과량 중앙값/최대 |
|---|---|---|
| 폭을 가진 **공백 아이템** | 347 (32%) | 192pt / 473pt |
| 크롭 박스 밖의 **정상 텍스트**(x≈584, 페이지 폭 612) | 717 (67%) | 22pt / 47pt |
| `x0 < 0` | 10 (1%) | — |

두 번째 무리의 폭은 멀쩡하다(`w / 추정폭` 중앙값 **0.95**). 좌표가 틀린 게 아니라
**종이 가장자리에 인쇄된 글이 실제로 크롭 박스를 몇 pt 넘는다.** 렌더러는 이걸 클립할 뿐이다.

4-2 폭 위생이 이걸 못 잡은 이유: 위생은 `w > W` 를 보는데 이 아이템들은 `w` 가 정상이고
**`x + w > W`** 일 뿐이다.

## 고칠 것 둘

### ① `lineBBox` 가 공백 아이템을 x 범위에 넣는다 — `extendRun` 과 규칙이 어긋났다

`js/text/lines.js` 의 `extendRun` 은 이미 `x1: blank ? it.x : it.x + it.w` 로
공백을 x 범위에서 뺀다. `lineBBox` 만 전부 넣는다. **같은 규칙으로 맞춰라.**

- 공백 판정은 `extendRun` 이 쓰는 것과 **같은 기준**을 써라. 기준이 두 벌이 되면 다시 어긋난다.
- **y 범위는 건드리지 마라.** 공백 아이템도 줄 높이에는 기여한다.
- 줄이 **전부 공백**이면 x0/x1 은 `min(item.x)`/`max(item.x)` 로 둔다(폭 0). 0,0 으로 만들지 마라.

### ② 페이지 사각형으로 클립

`lineBBox(line, pageRect)` — **선택 인자**로 받는다. 주지 않으면 클립하지 않는다.
`normalizeItems` 가 `pageInfo` 를 선택 인자로 받아 "판단 근거가 없으면 추측하지 않는" 것과
같은 방식이다. 이 코드베이스의 기존 관례이니 다른 모양을 발명하지 마라.

`js/text/layout.js` 의 `buildPageLayout` 은 `width`·`height` 를 이미 갖고 있다. 거기서 넘겨라.
단, **`width`/`height` 가 0 이면 넘기지 마라**(0 으로 클립하면 모든 bbox 가 0 이 된다).

**클립은 파이프라인 마지막에 한 번만.** 거터 히스토그램(4-5)·run 분할(4-4)·문단 분할(4-9)은
**클립 전 값**을 쓴다. 클립된 값을 먹이면 오른쪽 끝이 전부 `W` 로 뭉개져 레이아웃 판정이 무너진다.
`buildPageLayout` 의 어느 시점에서 bbox 가 확정되는지 **읽고 확인한 뒤** 그 자리에 넣어라.

### 클립이 결함을 가리지 않게

클립 후 `x1 - x0 <= 0` 또는 `y1 - y0 <= 0` 이 되는 줄은 페이지 밖에 통째로 있다는 뜻이다.
**실측에서는 0건이었다.** 생기면 클립이 진짜 결함을 덮고 있는 것이므로
`layout.stats.bboxDegenerate` 에 **개수를 세어 드러내라**. 줄을 버리지는 마라.

금지:
- **그 밖의 어떤 파일도 수정하지 마라.** `js/text/*` 의 다른 함수, `config.js`,
  `js/pdf/*`, `js/ui/*`, `css/*`, `index.html`, `spec.md`, `dev/*` 전부.
- `algoVersion` 을 **올리지 마라.** 올릴지 말지는 오케스트레이터가 정한다(아래 보고 항목 6).
- 기존 282개 테스트의 기대값을 바꾸지 마라. 하나라도 깨지면 **멈추고 보고하라** —
  깨진 테스트는 네 수정이 의도보다 넓게 퍼졌다는 증거다.
- 커밋·푸시 금지. 레포 안에 PDF·`node_modules`·`package.json` 금지.
- **원서 문장을 레포에 기록하지 마라.** 진단 출력도 분류·수치만 남겨라.
- 6b(원본 뷰)를 만들지 마라.

## 테스트

`node --test "apps/medreader/tests/*.test.mjs"` — **디렉터리 인자는 Node 24+Windows 에서 실패한다.**

새로 넣을 것:
1. 폭을 가진 공백 아이템이 x1 을 밀지 않는다.
2. 공백만 있는 줄의 x0/x1 이 0,0 으로 뭉개지지 않는다.
3. 공백 아이템도 y 범위에는 여전히 기여한다.
4. `pageRect` 없이 부르면 클립하지 않는다(기존 호출자 호환).
5. 오른쪽·왼쪽·위·아래 각각으로 넘치는 줄이 페이지 안으로 잘린다.
6. **클립이 중간 계산을 오염시키지 않는다** — 오른쪽 끝이 페이지를 넘는 줄이 섞인
   페이지에서 컬럼·문단 판정 결과가 이 수정 **전후로 같은지** 확인하는 테스트.
   (이게 가장 중요하다. ①②가 맞아도 이게 깨지면 6a 는 실패다.)
7. `bboxDegenerate` 가 페이지 밖 줄을 실제로 센다.

**변이 테스트**: 클립 상한을 `W` 대신 `W * 2` 로 일부러 망가뜨렸을 때 **어떤 테스트가
빨개지는지** 확인하고 보고하라. 아무것도 안 빨개지면 테스트가 헛돌고 있는 것이다.

## 실물 PDF 검증 (필수)

오케스트레이터가 진단 하네스를 만들어 두었다. **경로는 프롬프트로 따로 준다.**
스크래치패드에 `pdfjs-dist@5.4.149` 설치본과 `bbox-diag.mjs` 가 있다.

수정 후 같은 스크립트를 같은 인자(`--stride 2`)로 다시 돌려라. 기대:
- `badLines` **1,074 → 0**
- `lines` **24,460 에서 변하지 않음** (줄 수가 변하면 클립이 파이프라인에 샜다는 뜻이다)

두 수치를 **실제 출력 그대로** 보고서에 붙여라.
