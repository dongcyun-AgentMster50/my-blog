## 설계할 것
1. **무엇으로 찾나**
   - (가) **키워드 전문 검색** — 한 책 안 / 서재 전체(여러 권). 결과: 쪽·문맥 조각(앞뒤 몇 낱말)·적중 수. 결과를 누르면 그 쪽으로 가서 **적중 위치를 강조하고 스크롤**(10a 의 문자 구간 하이라이트·`charhl` 과의 관계).
   - (나) **제목·목차로 찾기** — PDF 자체의 개요(outline/bookmarks — pdf.js `getOutline()`, 쪽 대상 해석 `getDestination`/`getPageIndex`)가 있으면 그것을, 없으면 추출된 `heading` 문단에서 만든 목차. 장·절 이름으로 검색·이동.    - 의학 용어 검색의 실제: 대소문자·하이픈(`β-blocker`/`beta blocker`)·악센트·약어·복수형을 어디까지(과설계 금지 — 정규화 몇 가지와 접두 일치 정도로 충분한지 판단).
2. **색인 vs 그때그때 훑기** — 7,000쪽·여러 권에서 응답 시간과 저장 용량을 **추정이 아니라 측정으로**: 세 책의 `pages` 텍스트 총량(인계 문서: CMDT 2026 약 890만 자, CMDT 2021 약 960만 자)을 기준으로, (i) IndexedDB 의 `pages` 를 쪽마다 읽어 훑기, (ii) 낱말 역색인 스토어(DB 버전 ↑ 필요 — 9-1 마이그레이션 사다리), (iii) 문서별 압축 텍스트 한 덩어리를 메모리에 올려 훑기 — 각각 실제 시간·용량을 Node 에서 재라(브라우저 IndexedDB 는 못 재면 추정의 근거를 적어라). 저사양 폰(Realme GT7T) 기준 응답 목표(예: 한 책 1초 이내)를 정하고 고른 안의 근거를.
   - 색인을 만든다면 **추출과 함께**(9-4) 만들고 `algoVersion`/색인 버전 경첩을 둔다 — 인계 문서 교훈 "판본 경첩이 없으면 고친 것이 사용자에게 도달하지 않는다".
   - 추출이 덜 끝난 책: 끝난 쪽만 검색하고 그 사실을 보인다.
3. **화면** — 진입(리더 상단바 돋보기 / 서재 상단 검색), 검색창·결과 목록·"목차" 탭, 아랍어 UI(RTL)에서 영어 결과 조각의 방향(bidi — `ui/bididom.js` 재사용), 48px, 키보드 없이도(핸즈프리 로드맵 9b 의 음성 명령 "검색 …"과 겹치는지 언급만). 낭독 중 검색 결과로 이동하면 낭독은?(멈춤 / 그 위치에서 이어서 — 정하라).
4. **AI 호출 없음**이 원칙(무료 한도는 하나 — 17절 머리). 아랍어로 입력한 검색어를 영어 원문에서 찾고 싶을 수 있다 — 그때만 AI 번역을 쓸지는 **선택지로** 적고 기본은 끔.
5. **로드맵 배치** — 지금 순서: (공개 전 묶음 — 커밋됨·푸시 보류, 배포 안전장치 결정 대기) → Nour 공개 → 8d 문장 아래 번역 → 8e 가로(위치 미정) → 9a → 9b → 8c+8f 단어장 → 9c … 검색을 어디에 둘지 권장안과 근거(공개 전 필수인가? 운영자 요청이고 7,000쪽에서 쪽 번호 이동은 사실상 쓸 수 없다).
