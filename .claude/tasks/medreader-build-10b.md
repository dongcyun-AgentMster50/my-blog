## 지금 상태 (오케스트레이터가 확인함)

```
--bar-top     44px      상단바
--notice-h    24px      고정 고지 (+ 위아래 --sp-1 = --notice-total 32px)
--pager-h     72px      쪽 이동 바
--tts-h                 낭독 컨트롤 바 — [실측] 재생 버튼 64px + 패딩 + 테두리 = 81px
```

세로로 **44 + 81 + 72 + 32 = 229px** 가 본문/원본이 아닌 것에 쓰인다.
접은 화면(약 375×812)에서 본문에 남는 높이는 **580px 남짓**이다.

## 만들 것 둘

### ① 바를 얇게 — 세로 예산을 되찾는다

목표: **229px → 170px 안팎**. 정확한 값은 네가 정하되 아래를 지켜라.

- **16-G 터치 타깃 48px 하한을 깨지 마라.** 재생 버튼은 주 버튼이라 지금 64px(`--tap-lg`)인데,
  **56px 정도로 줄이는 것은 가능**하다. 48px 밑으로는 내리지 마라.
- 줄일 여지가 큰 곳: 바의 **위아래 패딩**, 버튼 사이 간격, 쪽 이동 바의 높이,
  상단바 높이, 고지 바 글자 크기·패딩.
- **고정 고지(`For education only`)는 없애지 마라** — 16-I 요구사항이다. 얇게만 만든다.
- 값은 **`tokens.css` 의 토큰으로** 바꿔라. 여기저기 하드코딩하면 다음에 또 어긋난다.
- `--tts-h`·`--pager-h`·`--notice-total` 을 **읽어서 띄우는 자리들이 이미 있다**
  (`reader.css` 의 `inset-block-end` 계산, `max-block-size`). 토큰만 바꾸면 따라와야 한다.
  **따라오지 않는 곳이 있으면 그게 버그다** — 찾아서 토큰을 쓰게 고쳐라.

### ② 스크롤 소유권을 하나로 정한다

지금 원본 뷰에는 **두 개의 스크롤 축**이 있다 — `.original-scroll`(쪽 안쪽)과 페이지 전체.
손가락이 어디에 닿았느냐에 따라 다른 것이 움직여 사용자가 예측할 수 없다.

**원칙: 리더 화면에서 세로로 움직이는 것은 언제나 하나여야 한다.**

- 원본 뷰의 **쪽 이미지 영역만** 스크롤한다. 그 바깥(바·고지)은 **고정**이고 페이지 자체는
  스크롤되지 않는다. `overscroll-behavior: contain` 으로 **스크롤 체이닝을 막아라** —
  안쪽 끝에 닿았다고 바깥이 따라 움직이면 안 된다.
- 리플로우 뷰도 같은 원칙으로 점검하라. 지금 어떤지 **먼저 측정하고** 보고하라.
- **가로 스크롤은 유지한다**(12-5 — 확대 상태에서 좌우로 밀 수 있어야 한다).
  막는 것은 **세로 체이닝**이다.
- 줌 하한은 `0.8×` 인데 접은 화면 폭 맞춤은 `0.61×` 를 요구한다.
  **하한을 "폭 맞춤 배율과 0.8 중 작은 값"으로 내려라** — 그래야 처음 열었을 때
  좌우로 밀지 않아도 쪽 전체가 보인다. 상한 3.0 은 그대로.

## 테스트

`node --test "apps/medreader/tests/*.test.mjs"` — **디렉터리 인자는 Node 24+Windows 에서 실패한다.**

CSS 는 Node 로 못 돌린다. **순수하게 떼어낼 수 있는 것을 떼어내라**:
1. **줌 하한 계산** — `min(폭맞춤배율, 0.8)`. 375px·768px·좁은 쪽·넓은 쪽에서 각각.
2. 줌 단계 이동이 하한·상한에서 멈춘다.
3. **토큰 합이 예산 안에 든다** — `tokens.css` 를 파싱해 바 높이 합을 재는 테스트.
   하드코딩된 숫자가 아니라 **파일에서 읽어** 검사하라. 다음에 누가 늘리면 빨개져야 한다.
4. 기존 테스트 전부 통과.

**변이 테스트**: 줌 하한을 0.8 고정으로 되돌리고, 바 토큰을 원래 값으로 되돌렸을 때
**어떤 테스트가 빨개지는지** 확인하고 보고하라.

## 스모크 테스트 — **여기가 이 단계의 핵심이다**

`preview_start {name:"blog"}` → `http://localhost:8000/...` 을 **새 탭**으로.
**패널이 숨겨져 있으면 `window.innerHeight` 가 0 이다** — 스크린샷을 한 번 찍어 띄운 뒤 측정하라.
모듈·CSS 캐시 전례가 있으니 고친 파일이 반영됐는지 `fetch('./css/tokens.css?t='+Date.now())` 로 확인하라.

**`resize_window {preset:"mobile"}`(375×812)에서 측정하라.** 접은 화면이 문제의 무대다.

1. `node --test` 전부 통과.
2. **세로 예산** — `--bar-top`·`--tts-h`·`--pager-h`·`--notice-total` 의 **실측 합**과
   본문에 남는 높이를 px 로 보고하라. 줄이기 전/후를 함께.
3. **★ 잘림 0 검증** — 원본 뷰를 열었을 때 **쪽 전체가 스크롤 없이 보이는가.**
   `.page-wrap` 의 `getBoundingClientRect()` 와 뷰포트를 비교해 **아래가 잘리지 않음**을
   수치로 보여라. 잘린다면 몇 px 인지.
4. **★ 스크롤 소유권** — 원본 쪽 영역에서 세로로 끌었을 때 **무엇이 움직이는가.**
   `.original-scroll` 의 `scrollTop` 과 `document.scrollingElement.scrollTop` 을
   **둘 다** 찍어서, 하나만 변하는 것을 보여라. 안쪽 끝에 닿은 상태에서 더 끌어도
   바깥이 움직이지 않아야 한다(`overscroll-behavior`).
5. **가로 스크롤은 살아 있다** — 3.0× 로 확대하면 좌우로 밀린다.
6. **터치 타깃** — 모든 버튼이 48px 이상. 실측 목록으로 보고하라.
7. **낭독이 그대로 동작** — 재생·다음·속도·반복. 10a 하이라이트가 어긋나지 않는다.
8. 콘솔 에러·경고 0건. CSS 물리속성은 허용된 예외 외 0건.

## 완료 보고 형식 (한국어로)

1. 생성/수정한 파일과 줄 수. **바꾼 토큰의 전/후 값 표.**
2. `node --test` **실제 출력**(tests/pass/fail).
3. 스모크 8개 각각 ○/× 와 근거. **2·3·4·6번은 반드시 측정값으로.**
4. 변이 테스트 결과.
5. **스크롤 소유권을 어떻게 정했는지** — 어느 요소가 스크롤을 갖고, 체이닝을 어떻게 막았는지.
6. 리플로우 뷰의 스크롤은 지금 어떤 상태였는지(측정 결과).
7. spec 과 다르게 구현한 부분. 없으면 "없음".
8. 다른 모듈에서 발견한 버그 (**고치지 말고** 보고). 남은 문제 3줄 이내.

**속도가 중요하다.** 테스트를 통과시키려고 spec 을 어기지 마라. 막히면 멈추고 보고하라.
**추측을 사실처럼 쓰지 마라** — 확인 못 한 것은 "확인 못 함"이라고 적어라.
