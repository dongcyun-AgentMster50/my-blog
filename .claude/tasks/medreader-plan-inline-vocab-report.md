## 2. 16-D0 결과 기록

- **VPN 켬**: [검증] 유효 · 3,300ms · 200, [시험 번역] 성공(아랍어 UI·다크). **VPN 끔**: `REGION` · HTTP 400 · 753ms, "키 문제가 아닙니다", [키 설정] 유도 없음. → **`[M]` 통과**로 기록했다. "방법 B"가 실제 시리아 응답을 잡았다. 실제 문구가 location 류였으므로 8-2 의 "알려진 빈틈"은 그대로 둔다.
- 기록 공백: VPN 끔 결과가 버튼별로 나뉘어 있지 않다. 다음 기회에 [검증]과 [시험 번역]을 따로 받으면 `GET /models` 도 막히는지 알 수 있다(판정에는 영향 없음).
- [검증] 3,300ms 는 한국(114~389ms)보다 10배쯤 느리다(VPN 경유로 추정). `TR_WAIT_MS` 4초가 빠듯할 수 있어, 8b 실기기 확인 때 Nour 기기의 head 응답 시간도 적도록 했다.
- **키 형식 경고**: 키가 헤더로 실제 통했으므로 글자는 전부 ByteString(U+00FF 이하)이고 줄바꿈이 없으며, 앞뒤 공백은 `trim()` 이 뗐다. 그래서 **가장 유력한 원인은 몸통의 출력 가능한 ASCII 중 클래스 밖 글자**(`.`·`~`·`+`·`/`·`=`)다. 길이 부족과 보이지 않는 글자 끼임은 가능성이 낮다.
  고칠 방향은 셋이다. (가) 키 원문 없이 글자 종류와 개수만 보이는 진단 한 줄. (나) 패턴을 `^AQ\.[\x21-\x7E]{20,}$` 로 넓힌다. (다) **`REDACT_PATTERNS` 도 같이 넓힌다**. 지금 패턴은 키에 `.` 가 있으면 그 앞까지만 지운다. 실제 키 문자열로 지우는 두 번째 그물이 없는 경로에서는 뒤 조각이 샐 수 있다.

**설정** `readalong.display = 'band'(기본) | 'inline'`. 리플로우 전용이고 원본 뷰는 늘 띠다. 탭 번역(8c)도 띠다.

**삽입 계약 I1~I7** (요지)
- **I1** 블록은 `span.ra-tr`(display:block)이다. **`span.line` 의 형제**로만 넣고 줄 span 의 자식은 건드리지 않는다. `charhl` 은 `span.line.firstChild` 의 오프셋만 보므로 좌표가 그대로이고, `.line` 계열 속성이 없어 줄 탭·`lineElement`·`flowLineIds` 에 걸리지 않는다.
- **I2** 앵커 = 그 문장이 끝나는 줄이다(`Unit.ranges` 마지막, 없으면 `lineIds` 마지막). 한 줄에서 끝나는 문장이 여럿이면 seg 순서로 쌓는다.
- **I3** "다음 문장 B 의 앞부분이 A 번역 위에 남는 것"을 **허용**한다. 원서 줄에서는 흔하다. 없애려면 텍스트 노드를 쪼개야 하는데 그것은 10a·6a 를 다시 연다. 완화책은 주석처럼 보이는 스타일이고, B 하이라이트는 두 조각을 그대로 칠한다.
- **I4** 넣는 때는 세 가지다. ① 쪽을 그릴 때 캐시에 있는 문장 전부. ② 문장이 현재가 될 때. ③ 지나간 문장에 늦게 온 번역은 펼치지 않고, 같은 높이의 한 줄 "눌러서 보기"로 둔다.
- **I5** 현재 문장의 블록이 상태(번역 중·실패+[다시 시도]·막힘)를 맡는다. 지나간 상태 줄은 즉시 지우지 않는다(위를 밀기 때문).
- **I6** `overflow-anchor: none`.
- **I7** 설정이나 언어가 바뀌면 전부 지운다.

**새 호출 0**: `buildUnits(flowParas(),'sentence')` → `sentencesOf` → 7-5 `translate` 키 → `cache.getMany` 순서로 다시 그리고, `pipeline` 은 import 하지 않는다. bidi 는 `appendBidiText` 를 쓰고, 괄호 속 영어는 화면에 남긴다.

## 4. 요청 2 — 단어장 설계 요지

- **진입**: 길게 누르기를 브라우저의 낱말 선택으로 둔다. 선택이 생기면 낭독 바 위에 선택 동작 줄 `[단어 번역]·[문장 번역]·[여기서부터 읽기]` 를 띄운다. 낭독 중 줄 탭 = 이동은 유지한다. 리플로우 전용이다.
- **번역 순서**:
  ① 단어장에 이미 있음 → 호출 0.
  ② **문장 번역 캐시의 괄호 원어에서 찾기** → 호출 0. 지시문이 용어마다 "번역어 (원어)"를 두므로, `ltrRuns` 로 괄호 묶음을 찾아 그 앞 최대 4낱말을 후보로 보이고 사용자가 확인한다.
  ③ 사용자가 [AI 로 번역]을 누를 때만 `kind:'term'` 요청을 보낸다. 지시문은 `prompts.js`, 10-1 골격을 따르고, 스키마는 원어·기본형·품사·번역·짧은 뜻이다. **묶음 최대 20개**로 보내고, 같은 낱말 + 문맥이면 캐시에서 꺼낸다.
- **저장**: `cards` 의 `kind:'term'` 이다. DB 버전은 그대로고 12 SRS·9c 백업이 그대로 이어받는다. 필드는 원어·정규형·번역·품사·뜻·문맥 문장(+번역 사본)·문서·쪽·추가일·수정일·메모·sm2 다. 번역·뜻·메모는 사용자가 고칠 수 있다. 문서별 보기와 전체 보기가 있다. **문서를 지워도 단어장은 남긴다**(`CASCADE_STORES` 에서 제외 — `db.js` 변경).
- **파일**: 브라우저는 파일 하나를 계속 고쳐 쓸 수 없으므로 "변경 사항 저장" = 새 파일 내려받기다. "마지막 내보내기 뒤 바뀐 n개"를 보여 준다.
  - CSV(엑셀): UTF-8 BOM·CRLF·RFC 4180, 영어 열 이름, `= + - @` 로 시작하는 칸은 `'` 를 붙인다.
  - Anki: TSV 와 `#separator`·`#columns` 머리 줄(가정).
  - **가져오기는 넣는다**: 같은 CSV 만 받는다. id 가 같으면 updated 가 새로운 쪽이 이긴다. 미리보기 "새/바뀜/그대로", 상한 2MB·5,000줄.
  - 9c 백업에는 `cards` 가 이미 들어 있다. CSV 는 사람이 읽는 부분 내보내기다.
- **개인정보**: 저장하는 것은 고른 낱말·교과서 문장·번역·메모뿐이다. 키는 절대 없다. 메모는 AI 로 보내지 않는다.

## 5. 로드맵 배치 권장

**8b → 공개 전 묶음 → Nour 공개(띠) → 8d 문장 아래 번역 → 8e 가로 → 9a → 9b → 8c + 8f 단어장 → 9c → 10 … 12 SRS**

공개 전 묶음 = documents 경합 · 러닝 헤드 · **원본 해상도(요청 4)** · **키 형식 경고**.

- **요청 4는 공개 전 묶음에 넣는다**(오케스트레이터 권장에 동의). 순수 함수 1개 + 상수 + 테스트뿐이고 algoVersion·DB 와 무관하다. Nour 가 이미 본 결함이다.
  - 새 규칙: `canvasRatio = max(1, min(dpr, √(8MP / CSS 면적), 4096 / 한 변))`. 66% 에서는 기기 밀도(3) 그대로 그리고, 3× 에서는 1.58 이 된다. 옛 규칙(2, 13.4MP)보다 메모리가 적다.
  - 표 크롭은 절대 배율 3 이라 리플로우 폭 표시에 충분하다. 바꾸지 않는다.
- **요청 1은 공개 전 필수가 아니다.** Nour 는 아직 띠를 본 적이 없고, 띠로 "아래에"가 충족될 수도 있다. 실제 반응이 (b)의 세부를 정하는 최고의 근거다. 호출 0·DB 무관이라 공개 직후 8d 로 바로 붙일 수 있다.
- **요청 3은 자동 회전 확인이 먼저다.** 꺼져 있으면 가이드 한 줄로 끝나고, 켜져 있으면 8e 로 간다.
  - 8e 는 높이 ≤ 520px 일 때 토큰만 바꾼다: 쪽 이동 바를 합치고, 상단바는 자동 숨김(아래 [≡]·위로 스크롤로 다시 표시), 띠는 2줄, 고지는 그대로다.
  - 800×360 기준 본문이 173/94 → 277/198px(띠 끔/켬, 상단바 숨김)이 된다. 폴드를 펼친 가로 화면은 compact 가 아니다.
- **요청 2는 8c 와 한 단계로 묶는다.** 같은 손짓 체계를 쓰고, 8c 의 문장 번역이 호출 0 경로의 재료다. 9a·9b(필수, 호출 0) 뒤에 둔다. 8c 가 운영자 순서 목록에서 빠져 있어 자리를 명시했다.

## 7. 위험

- **I3(B 앞부분이 번역 위에 남음)이 실제로 읽기를 방해할 수 있다.** 2단 조판 원서는 문장이 대개 줄 중간에서 끝난다. 8d 실기기에서 Nour 반응을 볼 것. 싫어하면 대안은 "줄 span 을 문장 경계에서 쪼개는 inline 전용 렌더"뿐이고, 그것은 `charhl`(firstChild 가정)·6a 이음새를 고치는 큰 작업이다.
- (b)는 쪽 길이가 약 2배가 된다. 원본 대비 한 화면의 원문이 절반이므로 눈 피로가 오히려 늘 수 있다. 그래서 기본값은 띠다.
- 단어 번역 호출 1회 ≈ 낭독 번역 5,900자분이다. 낱말마다 부르면 하루 13쪽분이 사라진다. 호출 0 경로(괄호 원어)의 적중률은 추정일 뿐이니 8f 에서 실제 번역문으로 잴 것.
- `findInSentenceTr` 의 "괄호 앞 최대 4낱말"은 기계적 자르기라 후보가 틀릴 수 있다. 확인을 사용자에게 맡기는 이유다.
- `db.deleteDocument` 연쇄를 바꾸면 기존 삭제 테스트(16-B)에 영향이 간다.
- Anki 머리 줄·Android 의 File System Access 부재·캔버스 상한(8MP·4096)·compact 기준 520px·폴드 화면 치수는 전부 `[가정]` 이다. 실기기와 Review 에서 확인할 것.
- 가로 compact 의 상단바 자동 숨김은 프로그램 스크롤과 사용자 스크롤을 가르는 6-5 의 800ms 규칙에 기댄다. 그 규칙이 틀리면 바가 깜박인다.
- 키 형식: `REDACT_PATTERNS` 를 넓히면 일반 문장 속 `AQ.` 로 시작하는 토큰도 지워진다. 지우는 쪽이라 받아들일 만하다.
