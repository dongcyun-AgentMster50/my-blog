> 너는 **Plan 서브에이전트**다. 앱 코드를 고치지 않는다. 결과는 `apps/medreader/spec.md` 에 새 소절로 쓴다 — O1 은 **17-5 아래 "17-5-1. 스캔본 감지·안내 — 운영자 실물(2026-10-19)"**, O2·O3 와 배치는 **19-1-1 아래 "19-1-2. 운영자 요청 O1–O3 — 분류와 배치"**. 기존 절은 고치지 않는다(바꿀 결정은 새 소절에서 "갱신"으로). 18절 새 행은 **추가만**. 같은 내용 요약을 `.claude/tasks/medreader-plan-o1-o3-report.md` 에. **커밋하지 않는다.** 한국어. 결정이 필요한 곳은 선택지와 권장안.

## 배경 — 운영자가 자기 영어 공부용 PDF 로 MedReader 를 쓰려다 막혔다 (2026-10-18)
- **O1 스캔본**: `G:/01_Language/01_English/grammar in use/Cambridge.Advanced.Grammar.in.Use.[2nd.edition.2005].pdf` — 307쪽, OmniPage Pro 15 산, **글자 층 0**(표본 11쪽 + 오케스트레이터 확인 38·39·46쪽 0), 쪽마다 스캔 이미지 1–2장, 본문 약 150 dpi. 원본 보기만 되고 낭독·번역 불가. **Tagged PDF 로 표시**돼 있어 OCRmyPDF 가 기본 옵션으로는 거절한다(`--skip-text` 필요).
  - 운영자 PC 우회(10-19): `py -m ocrmypdf -l eng --skip-text --rotate-pages --deskew --oversample 300` 으로 40–45쪽 시험 → 쪽당 2,590–3,311자, 이상한 낱말 약 2%. 글머리 기호·✓✗ 같은 기호가 "xx"·"©"·"CO"·"vot"(not) 등으로 잘못 읽힘. MedReader 레이아웃(앱 모듈)으로 보면 40쪽(연습 문제)은 1단 · 문제 번호 순서대로, 41쪽(설명)은 1단으로 잡혀 설명과 오른쪽 예문이 섞여 읽힐 수 있다(확인 필요). 전체 307쪽 변환은 지금 운영자 PC 에서 돌고 있다(결과 파일 `…[OCR].pdf`, 같은 폴더) — **Plan 은 이 파일을 기다리지 말고**, 있으면 표본으로 쓴다.
  - spec 17-5 결정: (c) 감지·안내 먼저 → (a) 브라우저 OCR 을 문서 단위로 켤 때만, (b) Gemini 비전 OCR 은 넣지 않음. 이번 질문: (c) 의 **우선순위를 올릴지**(아주 작다 — 쪽마다 글자 0 + 이미지 ≥1), 안내 문구에 "PC 에서 OCR 하는 법"을 넣을지, (a) 를 앞당길지.
- **O2 영한 혼합 PDF**: 원문 언어가 문서 속성 하나라 한국어 부분도 영어 목소리로 읽는다 → **문장(또는 문단)별 언어 판별 + 목소리 전환**. 메모리 원칙: "MedReader 대상은 여러 권·여러 언어 — 책·언어별 튜닝 금지, 원문 언어를 문서 속성으로" — 문서 속성은 유지하되 **글자 체계(스크립트)로 문장 단위 예외**를 둘 수 있는지(한글·아랍 문자·라틴 — 일반 규칙). 번역(원문 → 대상)과의 관계: 대상 언어와 같은 언어 문장은 번역하지 않는가, 번역 캐시 키·한도 영향. 실물 예시 PDF 는 없다 — 합성 예시로 설계하고 "실물 필요"로 적는다.
- **O3 목소리 고르기(미국/영국 억양, 남/여)**: 지금 목소리 고르는 화면이 없다(`tts.voice.*` 를 쓰는 UI 0, `pickVoice` 가 기기 내장 음성 중 규칙대로 고름 — 억양 임의). 이미 승인된 **8k**(spec 19-1-1 E1: 휴대폰 설정 따름 + 언어별 고르기 목록 + [들어 보기])에 합친다. 안드로이드는 성별을 휴대폰 TTS 설정에서 고르고 앱엔 언어 단위로만 보일 수 있다. PC Edge 는 "Microsoft Guy(미국 남)"·"Ryan(영국 남)" 등이 목록에 있다. **억양(en-US/en-GB)을 언어 안의 선택지로** 보여 줄지, 목소리 이름 그대로 보여 줄지.

## 계획할 것
A. O1: 감지 규칙(쪽 글자 0 + 이미지 연산자 ≥1 — 비용, pdf.js 로 이미지 유무 판정 방법), 문서 단위 판정(몇 쪽 이상이면 "스캔본"), 안내 화면·문구(네 언어), PC OCR 안내(OCRmyPDF `--skip-text` 포함 — 앱 안에 명령을 넣을지, 가이드 문서에만 둘지), (a) 브라우저 OCR 의 비용 대략(Tesseract.js wasm·언어 데이터 크기·쪽당 시간 — 문헌/경험치로, 측정 못 하면 `[가정]`) 과 앞당길지.
B. O2: 판별 규칙(스크립트 비율, 짧은 문장·숫자·약어 처리), 목소리 전환 경로(speaker 가 단위마다 lang/voice 를 바꾸는 비용·끊김), 번역과의 관계, 설정(켜고 끄기), 테스트 꼴.
C. O3: 8k 범위에 억양·성별 표시를 어떻게 더할지(Web Speech API 의 `lang`·`name` 만으로 — 성별 속성은 없다), 8k 지침에 넣을 문안.
D. 배치: 19-1-1 순서 안 어디에 O1(c)·O2·O3 를 넣을지. 무료 AI 한도 영향(대부분 0일 것).
E. 운영자 결정 필요 사항(선택지·권장).
