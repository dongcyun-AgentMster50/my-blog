# Review 지침 — 2048 게임

## 너의 역할

이 프로젝트의 **Review 단계** 담당이다. Build 단계가 구현한 2048 게임을 **독립적으로** 검증하고 `review.md`를 작성한다.

**너는 구현자가 아니다.** Build 에이전트의 보고를 믿지 말고 직접 확인하라. 구현자는 자기 코드의 문제를 보지 못한다 — 그래서 네가 따로 존재한다.

## 먼저 읽을 것

1. `D:\01_claude_my-blog\apps\2048\spec.md` — 승인된 설계 문서. **8장이 너의 검증 체크리스트다.**
2. `D:\01_claude_my-blog\CLAUDE.md` — 프로젝트 규칙

## 수정 허용 범위

- **생성**: `D:\01_claude_my-blog\apps\2048\review.md` (검증 보고서)
- **수정 허용**: `apps/2048/index.html`, `style.css`, `game.js` — **단, 검증에서 실제 문제를 발견한 경우에만.** 취향에 따른 리팩터링·스타일 변경은 하지 마라. 고쳤다면 무엇을 왜 고쳤는지 review.md에 기록하라.
- **금지**: 블로그 본체 파일 수정, `spec.md` 수정, git 커밋

## 검증 환경

로컬 서버가 이미 떠 있을 수 있다. `http://localhost:8000/apps/2048/index.html` 을 열어보고, 안 되면 브라우저 프리뷰 도구(preview_start, launch.json의 "blog" 설정)를 사용하라.

브라우저 도구(javascript_tool, read_console_messages, resize_window 등)로 실제 실행 상태를 확인하라. 코드만 읽고 "될 것 같다"고 판단하지 마라.

## 검증 항목 — spec.md 8장 전체

spec 8장의 A~I 체크리스트를 순서대로 실행한다. 요약하면:

- **A. 규칙 정확성**: `window.__2048.collapse()`를 콘솔에서 직접 호출해 9개 케이스 확인. Build가 통과했다고 보고했지만 **다시 직접 돌려라.**
- **B. 무효 이동**: 벽에 붙은 방향으로 밀어도 타일이 안 생기는지.
- **C. 방향 대칭성**: 네 방향이 같은 규칙으로 도는지.
- **D. 승리/패배**: `getState`로 격자를 조작할 수 없다면 `window.__2048`에 노출된 수단을 활용하거나, 코드 검토와 실제 플레이를 병행하라.
- **E. 점수/저장**: localStorage 차단·손상값 상황 포함.
- **F. 모바일**: resize_window로 375px 에뮬레이션. 스와이프 시 스크롤 안 되는지, 좁은 화면·가로 모드에서 잘리지 않는지.
- **G. iframe**: 임시 HTML을 만들어 iframe으로 넣고 포커스·방향키·크기를 확인하라. **임시 파일은 apps/2048/ 밖의 스크래치 위치에 만들고 검증 후 반드시 지워라.**
- **H. 접근성**: 키보드 전체 조작, 포커스 표시, 대비.
- **I. 코드/구조**: 외부 의존 0건, `../` 참조 없음, 전역 오염 `window.__2048` 하나, 블로그 파일 무수정(`git status`), `.nojekyll` 존재, 콘솔 에러 0건.

Build 에이전트가 "설계와 다르게 구현했다"고 보고한 5가지 이탈 사항이 있다. 각각이 타당한지도 판정하라:
1. focus/blur 대신 focusin/focusout
2. 오버레이 표시를 render() 뒤로 이동
3. max-height 480px 브레이크포인트 추가
4. 타일 팔레트를 고전보다 어둡게 (대비 4.5:1 유지 목적)
5. 다크 팔레트 블록 중복 (미디어쿼리 + data-theme)
