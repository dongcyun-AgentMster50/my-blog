## 1. 핵심 사실 (코드 근거)

1. **`cards` 스토어는 있고 비어 있다** — 인덱스 `docId`·`dueAt`·`term`, `kind` 인덱스 없음, 쓰는 코드 0건(`js/db.js:70-75`). DB 버전 3 그대로 12·13 을 할 수 있다(필드 추가뿐).
2. **`progress`(진도) 스토어도 쓰는 코드가 0건이다** — 17 #14 의 "speaker `linechange` 가 이미 `readLineCount` 를 갱신" 은 사실이 아니다(`js/ui/controls.js:214-218` 은 화면 진행 표시·readalong 커서만). 저장되는 위치는 `documents.lastPage`·`lastLineId` 뿐(쪽을 그릴 때 — `js/ui/reader.js:806·1577-1601`). "이 쪽을 끝까지 읽었다" 이벤트도 없다(`speaker.advancePage` `js/tts/speaker.js:755-790`).
3. **낭독 속도 실측은 아무 데도 없다** — `TTS.CHARS_PER_SEC 14`·`READALONG.CHARS_PER_SEC_TR 10` 은 워치독용 `[가정]`(`js/config.js:362-365·709-711`). 8b 에서 재기로 한 번역문 속도도 아직 가정이다. → 13-1 이 기록을 시작해야 한다.
4. **1만 자당 호출**은 `usage` 행의 `byKind.readalong`·`charsTranslated` 에서 나온다(15절, `js/ai/provider.js:209-283`) — 화면(8c-2 `usageView`)은 아직 초안. 없으면 spec 실측 1.7.
5. **쪽별 글자**는 `searchText.text`(8g)로 싸게 얻는다. 쪽당 글자 실측 `documents.readStats` 는 번역 대상 문장 글자다(`js/ai/readalong.js:207-215`).
6. **연쇄 삭제**는 `cards`·`progress`·`annotations` 를 함께 지운다(`js/db.js:451-454`). 8f 가 term, 11 이 저장 요약을 빼기로 했다.
7. **`dueAt` 의 형(숫자/ISO)이 아직 정해지지 않았다** — 8f 초안은 `dueAt = createdAt` 만 적었다. 섞이면 IndexedDB 범위 조회가 조용히 빠뜨린다 → 숫자 ms 로 정하고 읽을 때 ISO 도 받는다.
8. **`updatedAt` 충돌** — 복습이 `updatedAt` 을 올리면 8f "마지막 내보내기 뒤 바뀐 항목"과 9c 병합(`updatedAt` 새로운 쪽)이 망가진다 → 복습은 `reviewedAt` 을 따로 쓴다.
