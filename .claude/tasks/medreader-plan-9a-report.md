# 9a Plan 보고서 — 이어폰·잠금 화면 버튼 (2026-10-27)

지침: `.claude/tasks/medreader-plan-9a.md`. 결과: `apps/medreader/spec.md` 17-1 안 새 소절 **17-1-1. 9a Build 설계** `[신설 2026-10-27 — 9a Plan, 운영자 결정 대기]` + 19-1 9a 행에 `[수정 2026-10-27 — 9a Plan]` 표시. 앱 코드·테스트·review.md 변경 0, 커밋 0, 스크래치패드 사용 0(측정 스크립트 없음 — 읽기와 웹 조사만).

## 1. 핵심 사실 (코드 `b52ee00`)

- `navigator.mediaSession`·`MediaMetadata`·`<audio>` 사용 **0**. 지금 이어폰 버튼은 페이지에 아무 일도 하지 않는다.
- speaker 공개 함수 `play`·`pause`·`next`·`prev` 만 부르면 8d·8i-3·8m·readalong 이 화면 버튼과 같게 돈다 → **speaker.js 0줄 변경**으로 설계함.
- `next` 는 번역 단계(`tr`·`tr-wait`) 중이면 그 번역을 건너뛰고 다음 문장 원문부터(단계 → `src`). 쪽 끝 `next` 는 낭독 중일 때만 다음 쪽(8i-3 렌더 알림 대기), 멈춤이면 아무 일 없음.
- 6-4 hidden 규칙(controls 253–263)은 **visible→hidden 전환 때 한 번**만 돈다. 숨김 중 `play()` 가 불리면 그대로 읽는다 — 9a 가 처음으로 그 길을 연다 → 핸들러에 hidden 검사가 꼭 필요.
- 화면 꺼짐 낭독은 이 앱으로 잰 기록이 없다. 숨김 창에서 원본 보기 그리기가 끝나지 않는 관찰(review.md 3629)은 있다 → (다)는 원본 보기 쪽 넘김에서 5초 뒤 멈출 것 `[추정]`.

## 2. 웹 조사 (출처는 spec 17-1-1 2)

- 확인됨: Android Chrome 미디어 알림은 `<audio>/<video>` 재생 중, **5초 넘는 미디어**만(오래된 글 — Chrome 143 에서 같은지는 미확인). 핸들러를 건 액션만 알림 단추. Android 프레임워크(SDK 27+)는 헤드셋 단추 **두 번 = 다음**. 숨은 페이지 타이머 스로틀에서 **무음 오디오는 "소리"가 아니다**.
- 못 찾음: `speechSynthesis` 만으로 세션·버튼이 오는지, 화면 꺼짐에서 Web Speech 가 계속되는지(공식 문서·Chromium 이슈 없음), 세 번 누름 대응, 무음 오디오와 TTS 의 오디오 포커스 다툼 → 전부 `[가정 — 실기기]`.
- 주의할 위험(문서 근거): 세션이 없으면 미디어 버튼이 **마지막으로 소리 낸 다른 앱**으로 간다 → 이어폰 단추가 Nour 의 음악 앱을 틀 수 있다.
